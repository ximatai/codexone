# ADR 0003：首发限期限量正文恢复缓存

状态：accepted。日期：2026-10-21。来源：用户了解旧服务后明确选择，替代此前不保存正文的建议。

决定：首发加密保存恢复所需正文/图片；固定 TTL、多级容量限额、授权隔离、删除、密钥版本和恢复代际。默认不备份，不做历史浏览。初始容量建议 24 小时/32/128/512 MiB，待压力验证定稿。

原因：需要短期断线恢复能力，同时约束弱服务器磁盘、敏感数据留存及运维复杂度。缓存是可降级设施，主账本和 ID 归属屏障不能随之降级。

代价：新增加密/删除/容量治理。持久缓存不能解决所有上游上下文丢失，不能证明客户端已接收或工具未执行；无可靠重试/接收契约时明确不可恢复。旧备份恢复必须换 generation 防止残留缓存越界。

原始评审中的不留正文建议保留为历史，不再代表现行政策。[缓存规范](../specs/recovery-cache.md) · [架构 §9.1](../architecture/ARCHITECTURE.md#91-短期正文恢复缓存用户已确认首发)
