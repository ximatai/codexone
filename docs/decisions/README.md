# 共识决策

记录已采用的工作共识及理由，不代表方案不可调整。遇到困难或更好证据，按治理流程沟通；进度只见根 STATUS。

## 技术栈与组织

Swift 6 严格并发，NIO 掌控数据面，Vapor 承担管理 API，AHC 调用上游；SQLite 单节点。管理台 TypeScript/React/Vite 静态 SPA。Linux amd64 OCI/Compose，由 GitHub CI 构建，服务器不承担编译。

依据：传输实验表明应显式控制 channel 生命周期；单体和 SQLite 适合小规模自托管，静态前端无需 Node 运行服务。代价是维护窄传输层，SQLite 不提供多写 HA，Swift 并发检查不能替代事务与生命周期验证。

### 发行的数据卷与回环边界

Linux Compose 使用 host network 保留网关的回环监听，由宿主 TLS 反代接入；不为容器包装扩大监听面。data 默认使用唯一命名的 Engine 本地 volume，显式 nocopy；秘密保留独立只读文件。依据是共享 bind 的最小 flock 探针不能维持实例互斥，而 Linux 本地卷可维持；空卷 copy-up 还会重置目录属主。初始化只为新空卷设置 UID/GID，既有非空卷归属不符或目录读取失败均拒绝；隔离的短命 root init 不挂秘密、不联网，gateway 保持非 root。代价是数据与迁移备份由 volume 管理，不能把删除卷或复制旧快照当作升级/回退；证据见[安装验证](../changes/linux-distribution/verification.md)。

## 兼容优先用量治理

请求/并发硬限，token/图片按已知用量治理，金额估算；不要求所有订阅能力先证明严格消耗上界。限制并发与未知执行暴露，超预算停止新准入，明确披露可能超额。断线不等于未执行，不自动退款。

## 限期限量正文恢复缓存

首发包含恢复所需正文/图片缓存：加密、隔离、固定期限、多级容量限制、删除，默认不备份。它不构成永久历史库，不保证任意断线无损恢复，也不授权模型或工具自动重执行。具体客户端契约和参数需验证，未选择私有扩展协议。

## 文档与协作

STATUS 是唯一全局状态入口。规范独占行为规则，架构说明结构，决策仅保留必要理由。新 Agent 能从仓库接手；问题与更优建议及时沟通。讨论和中间记录在共识归纳后回收，由 Git 追溯。

## 首版以现有使用效果作为替代基线

以 Desktop 为主要兼容对象，CLI 补充；首版包含有边界的 Images edits、订阅额度观测、按 Key 用量诊断、旧服务迁移与弱服务器验收。理由是生成之外的参考图编辑、多种传输与日常管理已经属于实际需求，单纯完成新安装或 CLI 演示不能证明可替代旧服务。范围和验收以产品目标及协议/用量/运维规范为准；不复制旧服务内部设计或所有功能，也不放宽安全重试原则。

## 最小持久化适配

M1 使用系统 SQLite C API 的窄适配与串行 DB 队列，业务层只见原子命令。理由是当前切片需要少量条件事务、明确的连接初始化与失败语义，无需引入通用逐表 repository 或完整 ORM；代价是适配器自行管理语句和绑定寿命，必须以真实数据库与失败测试约束。Core 仍不依赖 SQL/NIO；CSQLite 仅为系统库桥接。

## M3 独立推进与 Key 轮换

2026-10-22 用户允许保留 M2 Desktop UI 与恢复契约缺口，先推进独立 M3；两项仍为未完成验收，不将 CLI 等同 Desktop，不提前建设没有可使用读取路径的恢复缓存。Key 治理先使用受控上游，后续再扩展托管账号与调度，避免把凭证刷新等价性和下游主体治理混成一次变更。

Key 轮换保留标识和治理计数，只替换验证材料；理由是轮换不应赠送新请求/预算额度，历史用量与同主体归属也应连续。显式创建另一个 Key 仍是独立治理操作。最小管理 API 使用独立管理员 Bearer、只允许非浏览器本机请求；浏览器 session/CSRF 和完整管理体验须在界面切片单独交付，未以 Bearer 页面存储替代。

管理面同样由 NIO 拥有连接/正文读取/关闭，完整请求交给 Vapor 路由；理由是实际慢速正文实验中，单纯路由超时不能证明底层连接与 collect 资源已结束。复用现有连接 owner，不改 Core 用例、不开额外网络 listener，也不为绕过寿命问题引入代理服务。


## 托管账号准入的语义版本

托管账号 dispatch 快照必须在持久准入事务中与当前账号/Key 一并复核；凭证准备不算取得租约。即使物理表未改，v4 仍升级核心库版本，理由是旧二进制会忽略 admission JSON 的新增字段，不能仅靠可选字段保持“兼容”而丢失授权屏障。代价是 v3 也须停服显式备份迁移；历史缺少快照的 admission 保持可读，执行责任不被删除或重新解释。


### M3 被动额度与统计隔离

v5 显式升级引入执行时间/结果与账号观察/健康；历史缺时间不从日窗口推造小时。额度只作被动 GET，不从单一窗口实现全模型硬禁用，附加额度/credits 含义未被模型配置覆盖。执行明确 401/429/5xx 决定版本屏障/模型冷却，持续用量责任不随健康变化释放。统计用独立只读 WAL connection 和单查询预算，避免图表扫描进入关键 writer 队列；大整数指标以字符串传输，缺证据继续暴露 unknown。代价是增加一个受主库寿命监督的只读连接与 v1—v4 的离线迁移，不能据此宣称长期容量或真实订阅验收。

## 主密钥维护的离线语义屏障

主密钥采用一个 active、有限 decrypt-only 的独立私有 keyring，沿用 v1 AAD/信封；再加密先独立备份，在同一离线实例锁下分页 CAS 与检查点同事务提交，不改凭证版本、授权或刷新 intent。即使表结构不变也升 schema v8，理由是旧 v7 二进制不会识别新检查点，可能绕过中断维护门禁。代价是旧库须显式迁移，旧 v7 完成 bundle 仅通过显式恢复升级；未完成 job 拒绝服务并需原 active 续作。

旧 key 是否可退役取决于所有存量引用与保留备份，不以线上轮换完成推断。工具核对候选 keyring、声明完整的保留清单及 bundle 恢复来源；原始备份的外部恢复审计、未知副本与销毁事实仍由操作者负责，不自动删除 secret。命令和边界见[主密钥维护](../development/master-key-maintenance.md)。

## 物理空间与关键收尾隔离

磁盘压力采用独立实际分配的私有储备文件、水位滞回和 writer 队列最后复核；不把剩余逻辑页或可删缓存当结算储备。先暂停报表/普通管理/观察/诊断，再停止新 intent；关键绑定/结算/刷新收尾及收紧权限仍可使用储备。理由是队列预留不能防止 WAL、报表长读或备份吃掉物理空间；代价是固定预留空间及低水位暂时拒绝可选工作。实际写满仍可能失败，已有持久 intent 保留为 unknown 恢复依据，不许因无法补写 pending 而丢责任。

Runtime 只拥有一个顺序采样/checkpoint owner；磁盘操作留在 Adapter writer 队列，认证观测与健康只读缓存。离线复制按页复核源/目标余量，不能通过维护耗尽核心空间。默认水位是预防性边界，正式宿主容量与完整 RSS/FD/task 回稳另行验收，见[存储压力](../development/storage-pressure.md)。
