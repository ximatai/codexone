# 正文恢复缓存

定义尚未交付的有限正文恢复目标及加密、隔离与容量要求。

- C01：后续恢复功能须提供所需正文/图片缓存；固定期限、限量、认证加密，主密钥与库分离，按版本管理。不得保存认证头/访问或刷新令牌，不作永久历史库。
- C02：按 principal、命名空间、身份和原执行隔离；读取重查当前权限、主库归属与恢复代际。相同正文不能充当重复执行证明。
- C03：同时限制单次/主体/实例字节、条目、物理文件/WAL、在途写入和队列。读取不续期；具体参数通过弱服务器容量验收确定。
- C04：完整性只由持久提交的连续输出和可信终态确认。队列入队或 socket 写完成不证明客户端已接收，交付位置不确定必须明确保留。
- C05：恢复不重新调用模型/工具、不新建生成 attempt、不重复扣收上游用量。内容缺失、过期、归属不明或无可靠客户端恢复契约时明确不可恢复，不能自动改成新生成。
- C06：缓存故障或超限可降级，不绕过主库准入、ID 暴露和结算屏障；缓存加密/清理/批写有独立容量约束，不能抢光核心持久化配额。
- C07：过期读取立即拒绝；删除/关闭与排队写入之间须有原子代际检查，防止清理后回填。删除正文不删除账本、未知执行和必要归属。
- C08：默认排除备份、导出、诊断和崩溃转储；主库 restore 更换代际，停止旧写任务、清空旧缓存，不能复活快照外或已删除内容。
- C09：低磁盘优先停止/清理缓存，为核心保留空间；清理覆盖 WAL/空闲页，不承诺 SSD 物理残留安全擦除。
- C10：至少证明一种实际可用、明确客户端/版本/调用方式的恢复路径。先验证关联、输出消费和失败语义，再建设重型存储；不预设私有协议，不把 fixture 或缓存写成功当作产品恢复验收。

管理台显示容量、到期与降级，支持删除；缓存不默认提供历史浏览/搜索。具体接口设计涉及新业务行为时及时沟通。

## C11：现服务恢复效果对照

恢复功能发布前必须对已声明 Desktop 路径分别验证下游断开、上游提前关闭、网关重启、会话/归属过期，以及文本/工具/图片执行中断。每种情形记录执行确定性、可读取的已有输出、是否保持续接、客户端需采取的动作和差异；这些是兼容验收结果，不是自动重放授权。

与旧服务行为有差异时必须说明原因及使用影响；无安全恢复路径的情形明确返回不可恢复或执行不确定，不伪装已成功恢复。恢复范围变化影响替代目标时须在切换前与用户确认，不能以笼统“不保证无损”跳过实际场景验证。
