# 持久化与运行规范

定义存储、备份、迁移、密钥与运行维护的安全约束。

- O01：首版必须单节点/单进程、本地可靠磁盘 SQLite，不支持网络共享盘或多写实例；WAL、synchronous=FULL、外键和 busy timeout 必须逐连接初始化/验证。阻塞 DB 工作不得在网络 event loop 执行，不得跨流式持有事务。
- O02：启动必须校验 schema、密钥、实例锁并恢复 intent/pending/exposure/auth_uncertain，再开放对应准入；数据库不可写必须停止新准入。最终化失败不得因 pending 标记没写成功而丢已持久 intent。
- O03：迁移、restore、密钥维护与服务必须共用实例锁；在线备份由持锁服务内部单一 owner 执行；兼容性检查/备份成功后方可迁移。旧快照恢复必须维护态、披露缺失区间、冻结受影响窗口并经审计重建额度基线，不得自动恢复旧余额后 ready。
- O04：备份必须使用一致性方式，验证密钥版本依赖和恢复；可选在线定时备份在 writer 外分步复制，自检成功后保留最近 7 份，失败不得删旧份；核心备份不含恢复正文缓存。回滚必须区分 schema 兼容二进制回滚与旧快照恢复。
- O05：shutdown 必须停止新准入、有界 drain、关闭 channel/移交最终化、await 任务、有限 flush、依次关闭客户端/数据库/event loop。超时未结必须可在启动恢复。
- O06：首发支持 Linux amd64 OCI/Compose；CI 构建镜像，运行时不需要编译器或 Node。ARM/systemd 必须独立验收后才能声明支持；反代须验证 SSE/WS、大小/超时和可信头。
- O07：指标必须低基数，不以 request/Key/response ID 做 label；普通日志不得存正文/图片/秘密。必须观测队列、取消回收、RSS/FD/task、DB/WAL、未知暴露和缓存降级。
- O08：发布必须给源码/镜像可追溯标识、配置契约、升级/备份/回退证据。健康探测不得调用付费模型；账号耗尽不能触发 liveness 重启循环。

## O09：持久与恢复细则

首版显式设置 WAL + `synchronous=FULL`；所有连接初始化并读回验证 `foreign_keys=ON`、synchronous、busy_timeout，数据库初始化验证 WAL。使用有限繁忙重试与专用有限 DB 线程池；不在 NIO event loop 执行阻塞 I/O，不跨流式持有事务。FULL 的持久性以磁盘/文件系统正确执行同步为前提，不承诺抵御失信硬件。[synchronous](https://www.sqlite.org/pragma.html#pragma_synchronous)、[foreign keys](https://www.sqlite.org/foreignkeys.html#fk_enable)

启动扫描所有旧 boot 的 held/dispatch_intent/unfinalized：确定未 dispatch 的可释放，其余默认 pending，重建其 exposure 占用；同时处理未完成 refresh_intent 为 auth_uncertain，完成后才发布路由快照。不能因 pending 标记未写成功而丢掉。正常进程崩溃恢复与主机掉电/存储故障分开验收；kill -9 仅证明前者。FULL 不允许作为未测掉电恢复的证据。

实例锁由服务、migration、restore 和密钥维护命令共同使用；离线迁移无法取得锁立即非零退出，不能旁路在线服务。命令先校验二进制与 schema 兼容范围，备份成功后迁移；失败回滚事务或保留 maintenance 状态、输出明确修复指引，数据面不得 ready。服务只做兼容检查，不自动执行破坏性迁移。

恢复旧快照总进入 `maintenance -> restored_unreconciled -> ready`：恢复工具记录快照时间、来源和恢复时刻，展示缺失区间；扫描快照内活动项，且明确快照之后的已执行项可能完全缺失。管理员选择并审计恢复后的额度基线（默认冻结受影响窗口/重发新窗口额度，不自动复活旧余额）后才启用准入。在线数据库完整性正确不代表快照缺口已核对。

绑定保留期须覆盖公布的续接窗口，过期/歧义对象不得自由调度；在途与核对中执行不做普通 TTL，已结算/关闭明细按 U15 的 90 天策略汇总保留。诊断/审计的保留期及磁盘水位依据容量与恢复需要确定并公开，不把候选数值作为承诺。

启动时为 binding 索引与待核对记录预留磁盘；低空间先暂停报表/新备份/可选聚合、清理允许过期诊断并告警，到安全阈值停止新准入，保留结算空间。空间分级采用真实用户可用空间、物理结算储备及 WAL；新准入必须在 writer 队列最后复核，可选查询/写入先退让，撤销权限及既有绑定/结算/刷新收尾保留。单一 Runtime 监测 owner 有界采样/零等待 checkpoint，容量拒绝不导致进程重启；真实核心写失败依赖 intent 恢复。具体默认水位/滞回及观测边界见[存储压力](../../operations/storage-pressure.md)。监测 WAL/checkpoint、长读事务、DB busy、备份大小与空闲空间；备份不能无限占满 data volume。在线备份用 SQLite backup API 等一致性流程，不仅复制 .sqlite 而漏 WAL。[Backup API](https://www.sqlite.org/backup.html)

## O10：安全与观测细则

本地 Key 高熵、不可逆验证存储、首次显示一次；principal 与 Key 分开以支持轮换。权限覆盖端点/模型/工具/图片/pool/对象范围/大小/速率/并发。普通撤销默认停止新请求与新 WS turn，在途完成；紧急撤销关闭在途并保留结算，操作前展示影响。管理 session 独立、HttpOnly/Secure/SameSite、CSRF/Origin 校验、一次性初始化秘密；不把普通 Key 当管理员认证。

凭证使用认证加密和 key version，主密钥来自独立只读 secret；数据库、镜像、浏览器与日志不含明文。密钥轮换先加入新 active key，旧 key 保持 decrypt-only；分页再加密带 CAS/checkpoint，可中断恢复；完成后验证所有当前密文可解及备份清单所需版本。只有对应旧备份已重加密或明确销毁、恢复演练通过、无存量引用时才能删除旧 key；仅“线上轮完”不能销毁备份依赖。当前命令采用离线独占锁、先完成独立备份，再每页最多八个账号 CAS/检查点同事务写入；凭证版本/授权/刷新 intent 不变。未完成 job 拒绝普通服务启动、保留全部解密密钥并显式续作，完成前复核全部密文。候选 keyring 的退役核对须覆盖完整保留 bundle、对应恢复记录及迁移前 raw 备份依赖；外部清单完整性、raw 恢复审计和销毁事实不能由工具代证。容量、命令与边界见[主密钥维护](../../operations/master-key-maintenance.md)。

上游 origin/端口/解析 IP 允许策略、TLS 验证、禁重定向、可信代理范围防 SSRF 与头伪造。自定义私网 origin 需管理员显式配置；用户图片 URL 不由网关默认抓取。请求/事件、分片累计、解压字节、multipart 总量均有硬限制；WS 压缩首版默认关闭。

普通日志、指标及审计不记录正文/图片/凭证/签名 URL；正文仅允许进入 §9.1 的加密恢复缓存，不能混入诊断日志；诊断显示阶段时间线、归属选择理由、策略与计价版本、取消与释放时间、pending 原因。管理台围绕身份、Key/策略、请求/会话、用量/待核对、备份与配置，不扩展成通用控制平台。

swift-log + swift-metrics 接导出适配器；指标不以 requestID/Key/responseID 做 label。重点观察队列字节、写等待、task/FD/RSS、取消释放、刷新、未知暴露、账本/DB 和 WAL。完整 tracing exporter 可延期，不承诺未验证 SDK 支持。关键审计/账本可靠保存，非关键统计有界采样。协议拒绝日志仅记录固定允许列表中的错误码、状态及服务端生成UUID；未知码归other，进程全局按单调时钟每60秒最多16条，溢出直接丢弃，无正文、头值、路径、客户端lane或任意Error描述。

## O11：发行与容量验收细则

镜像必须非 root、版本化配置、独立 data/secret 挂载，公布可追溯镜像/源码标识与校验和；只读根文件系统及运行所需可写挂载须实际验证。反代须覆盖 SSE 不缓冲、WS Upgrade、长连接期限、大小限制与可信头。ready 必须校验密钥/schema/恢复准入，live 只验证进程健康，容量耗尽不能导致重启循环。

发行反代模板分别承载数据与管理 TLS 域，保留管理公开 authority（含端口），不依赖 forwarded 头授权；生成转发禁止自动重试，客户端断开须关闭对应上游且不自动释放 unknown。SSE 关闭响应缓冲，WS 显式升级。普通反代日志不得记录请求 URI/查询、认证与正文；私有故障诊断须单独受控。模板默认大小与空闲超时需按已验证模型/profile 明确配置，不能把空闲超时等同请求总期限。

正式性能和容量指标须基于实际 Linux 硬件、负载、HTTP keepalive、WS 与图片峰值证据确定。资源回稳测 RSS/FD/task/队列，进程 kill 与系统/存储故障分别验收；不把 socket 释放包装成上游停止执行或收费。

## O12：基础进程与健康契约

启动配置必须先校验再打开 listener；端口只允许 0...65535，非零数据/管理端口不得相同。基础入口默认仅 loopback，0 用于临时分配。无效配置错误不得回显原始值；`--check-config` 不启动服务。

显式 `CODEXONE_LISTEN_ADDRESS` 增加同端口的第二个数据/管理 listener，回环保留。仅接受本机私有 IP 字面量：IPv4 10/8、172.16/12、192.168/16、100.64/10，IPv6 fc00::/7；禁止公网、通配、主机名、zone ID。配置无效返回 78，不回显值；本机地址由实际 bind 确认，部分绑定失败关闭并等待已建 listener/连接。`CODEXONE_ALLOWED_NETWORKS` 缺省或空为上述私有网段加 127/8、::1/128；非空为至多 64 个逗号分隔的私有/回环子网 CIDR，不接受空项、空白、畸形或扩大范围的 CIDR。只在第二个 listener 的 accepted socket 上按真实 peer 校验，HTTP decoder/请求读取前关闭不允许连接，不采用任何 forwarded 头；回环 listener 不受来源限制。两 listener 共享既有连接/执行容量与关闭 owner，不另增额度。

LAN 启动只输出一行明文风险警告，不打印秘密或配置值。`GET /api/system` 增加 `transportMode`：默认/反代为 `loopback`，启用第二监听地址为 `lan_http`；它表示网关监听模式，不判断上游或反代 TLS。LAN `--check-config` 增加 `transportMode=lan_http` 而不输出地址，默认输出保持原样。管理员每页（包括登录页）常驻中文风险提示及[风险说明](../../operations/tls-proxy.md#局域网-http-风险)链接。

数据/管理入口的 `GET /health/live` 表示进程存活；`GET /health/ready` 只有实际执行先决条件满足才为 200，否则 503，不能由监听成功推导可接单。未配置的生成请求须明确拒绝。ServiceLifecycle 统一拥有信号/子服务寿命；部分启动失败或取消应关闭并等待其他服务释放。健康连接的关闭不得等待客户端补齐未完成的请求体；信号回归须同时覆盖空闲连接和半截请求。

## O13：旧服务替代与可回退切换

首版必须有 CodexLB→CodexOne 的独立迁移方案和演练：域名/反代、端点前缀、客户端 provider 配置、账号凭证、Key/主体/策略、必要的用量基线及历史归属去向。采用脱敏/合成数据演练，真实导入和切换另经授权；不直接复制旧 SQLite 并视为新服务库。

方案必须列出原值可保留、需转换、必须重新授权/换发和不迁移的项目。旧 Key 只有验证材料可安全复用且授权策略等价时才能保留；仅有不可逆哈希不能还原明文。不能保留时提供换发/客户端变更清单并在切换前确认，不能静默使现有 Key 失效。上游凭证导入须验证稳定身份、加密版本和刷新能力，不导入未知语义对象冒充可续接状态。

切换前必须演练原域名下的健康、Desktop 文本/工具/压缩/图片生成与编辑、按 Key 权限及管理流程，并列出存量会话能否继续和用户动作。旧服务备份保持独立、受保护且可验证，暂停接收新请求后有界处理在途；新旧进程不得共写库或无协调刷新同一旋转凭证。回退步骤须覆盖路由、配置、凭证变化、切换期间新用量及未知执行的核对，不能只恢复旧数据库余额。发行通过不自动授权迁移 用户服务器。

## O14：弱服务器容量门槛

首版必须在 Linux amd64、约 1.6 GiB 物理内存的参考宿主或可解释的等效约束下验收；注明 CPU、宿主其他负载、容器限制、swap、磁盘与实际流量包络，单纯设置容器内存限额不能代表全部宿主条件。预算须为操作系统及共存服务保留余量，不以耗尽宿主或持续 swap 抖动换取通过。

必须测混合多 Key 的 HTTP/WS、长连接、预热/压缩、generation/edits 大负载和恢复缓存，记录吞吐/并发、延迟、错误及 RSS/FD/task/队列/DB/WAL/缓存峰值与回稳。并发、大小、队列、缓存和保留期从这些结果确定并公开；过载应有界拒绝而非无限排队或失去结算。低磁盘、缓存/WAL 增长及备份空间不足须有故障验证，容量不足不得反复重启或耗尽核心写入空间。未实测不得声称在目标弱服务器可替代旧服务。

## O15：持久执行功能的本地边界

可选 `CODEXONE_DATA_DIRECTORY` 为绝对路径，未配置时不建立执行库；配置后在监听前完成实例锁、空库 v10 初始化及未结执行/刷新 intent 恢复。存储就绪本身不授予上游/Key 权限。路径不进入配置检查或错误输出，新建目录/数据库/锁使用限制性权限。

v2 引入托管 Key 与变更审计，v3 新增账号认证密文/刷新 intent 与独立审计；v4 增加 dispatch 快照准入屏障；v5 新增 UTC 时间、结果/请求标识、额度/健康与有界拒绝诊断；v6 增加图片授权语义，历史缺失字段按保守权限解释。当前 schema 与迁移/恢复屏障见 O16。迁移先持实例锁核对兼容性/完整性，通过 SQLite Backup API 产生同目录私有一致性备份并同步，再事务更新 schema。失败的 `.partial` 不算有效备份；失败回滚 schema、保留源库与备份。迁移保留升级前 intent，普通启动再恢复 unknown/auth_uncertain。不能丢弃新账本后直接切回旧快照；账号密文与其独立主密钥须分开保护并共同规划恢复。

DB 执行使用专用串行队列，普通命令最多 16 个、最终化命令另保留 16 个位置；最终化最多 16 个 ticket，先取容量再提交任务。busy timeout 为 250ms，失败停止新准入，重启恢复后再开放。

每账号活动 intent 上限 16，超出可重试 429；全局/主体/身份未结与全局每日请求/预算不阻断，只有显式 Key 限额限制该 Key。移除 attempt 100000 行准入硬上限，以参考阈值及磁盘水位观测。字符串、最近 128 个证据版本和 DB/finalizer 队列等原有安全边界不变。Runtime 单一 ExecutionMaintenanceSupervisor 顺序 await 每轮维护，再等待 60 秒；关闭 await 后再关闭数据库，批次/事务与缺失语义见 U15。



## O16：核心快照维护闭环

当前 schema v10 新增日汇总、unknown 起点/关闭标记、绑定到期时间及并发峰值；保留 v7—v9 的恢复、再加密和显示名语义。普通启动仅接收 v10；v1—v9 须先停服、共用实例锁，先生成私有 `.pre-v10-<id>.sqlite` 一致性备份，再一次性启用 incremental auto_vacuum（需要 VACUUM），最后在事务内迁移 schema。VACUUM 与 schema 事务不能合并：重写失败保留原库；schema 失败回滚至旧版本（可能已启用增量回收），保留备份并可重试。旧二进制拒绝 v10，不允许原地降版本。大库耗时/空间与维护步骤见[快照维护](../../operations/snapshot-maintenance.md)。

独立核心备份通过 SQLite Backup API 生成私有完成 bundle，manifest 记备份 ID/快照时间/来源 generation/schema/摘要/主密钥依赖，最后发布并同步；恢复先校验完整性和密文解密依赖，只接受全新空目标。持久 restore-pending 屏障先于页面复制，不完整目标拒绝启动；完整目标必须 `restored_unreconciled`，不能由 SQLite 完整性正确推导 ready。快照内 intent 保守转 unknown，旧对象绑定失效；恢复 Key 的旧验证材料失效、订阅账号需重新授权，防止复活已撤销权限或自动重用旧旋转凭证。

审计核对显式绑定 restore ID、CAS 版本、非秘密审计编号、缺失未结数量/金额和冻结截止时间。首次核对的冻结至少覆盖核对当日 UTC 窗口及恢复日窗口，并继承更长的既有冻结；新窗口和新授权配额不代表旧余额恢复。缺失未结按额外聚合全局暴露保留作观察，不阻断准入，不能伪造每 Key 归属或随窗口自动释放；原已知 unknown 按原归属进入 24 小时核对期。后续新证据修订同样 CAS/追加审计，不能覆盖历史或自动退款。未核对/冻结中的准入返回 maintenance_required，管理查询仍可用。恢复时间在复制复核后记录；审计覆盖快照至首次核对的风险区间。恢复库拒绝旧静态单身份配置，须转托管 Key 或账号池，避免虚假就绪。复制前须同步新目标的父目录及持久 restore-pending，失败不得发布。命令和保守额度选择见 [维护操作](../../operations/snapshot-maintenance.md)。

首页管理提醒通过现有 `StorageMonitoring.storageObservation` 只读快照呈现低盘保护：degraded（可选工作退让）或 blocked（停止新准入）均为 critical `storage_pressure`；unknown 或核心不可用显示 `attention_source_unavailable`。不为提醒增加采样任务或改变水位、滞回与结算空间责任，接口契约见[管理产品规范](control-plane.md)。


人工和期满关闭使用 maintenance_events 治理审计（90 天，与其他维护审计容量隔离），action 为 release_unknown，记录数量、截止时间及执行时间，不记录请求正文、凭证或请求标识列表。审计写入失败时整体事务回滚，不解除部分容量；恢复及后续证据仍遵守 U07。


## 在线定时备份与日志

可选 `CODEXONE_BACKUP_DIRECTORY` 须为已存在、当前运行用户所有的绝对私有可写目录（0700、无末级链接），同时须配置核心数据目录；未配置不启动任务。Runtime 单一顺序 owner 启动后等待 10 分钟，其后每轮工作结束等待 24 小时，无积压队列。服务持实例锁，以独立只读 WAL 连接在 writer 外运行 SQLite Backup API；每步最多 128 页并让出，busy/locked 短暂退让，复制最多 5 分钟，关闭取消并 await 后才关闭主库。不持跨步读事务；持续写入导致复制重启时仍受期限与 1 GiB 硬上限约束。

复用离线 bundle 与密钥依赖、摘要、完整性校验，manifest 由完成快照生成。`online-<时间>-<UUID>.partial` 为未完成目录，下次 normal 轮次清理；自检通过后原子发布完成目录并同步父目录，再按快照时间与文件名排序裁剪至 7 份。只管理该命名空间，保留手工 bundle 和其他文件；异常记录失败且保留旧份。源与目标保留可选空间余量，复制批次复核目标空间；压力非 normal 或核心不可用时跳过/中止并记录，不进入核心写事务，不因备份失败停止服务。

目录总量超过 5 GiB 或单完成 bundle 超过 768 MiB 提醒，不自动删旧份换空间。认证健康字段、36/72 小时与未启用提醒见[管理契约](control-plane.md)。备份与主密钥须分别异地保存；同机独立卷不防磁盘丢失。Compose 全部服务以 json-file 的 10m × 5 轮转普通日志，不裁剪核心审计/账本。
