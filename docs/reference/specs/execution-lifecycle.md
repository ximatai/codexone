# 执行与连接生命周期

定义准入、发送、绑定、结算和任务结束的持久责任。

## 持久执行

- E01：每个 attempt 必须在 dispatch 前持久记录身份、意图和预留；准入失败不得发送上游。
- E02：执行状态、网络状态和未知消耗必须分开。取消本地连接不证明上游未执行；不能提供跨数据库与上游的 exactly-once 保证。
- E03：对外可引用 ID 必须先持久提交主体/命名空间/账号/对象/attempt 归属，再暴露。绑定失败停止输出，不跨账号重放；缓冲大小受限。
- E04：最终化必须有预先保留的有界处理容量和单次移交路径。结算幂等，移交后的可信迟到用量仍需去重合并，不能丢失或重复扣收。
- E05：数据库失败或关闭超时以已持久 intent/预留恢复未知状态；不得依赖失败后再写一次 pending 才能恢复，不自动退款。

## 连接与任务

- E06：WS 握手只做本地认证/容量管理；首个有效 create 串行决定上游身份。绑定后连接不换账号，后续 turn 重查权限与归属。
- E07：同 lane FIFO，跨 lane 有总容量限制；每个上游 socket 单 reader、串行 writer，禁止共享迭代器并发读取或交错消息分片。
- E08：任务/continuation 必须有 owner 和单次结束路径；队列按字节与条目双限，入 task/actor mailbox 前取得容量。慢消费者/拥塞超时关闭整连接，并逐 turn 最终化。
- E09：channel inactive、超时和显式取消汇入统一关闭路径，关闭 I/O 并取消/等待子任务；网络关闭不得反向等待结算造成循环。原生 WS 的下游关闭先按 [P14a](protocol.md#p14a原生-ws-客户端控制与前向兼容)停止接收并进行最多 10 秒的有界终态续读；直连与 TLS 反代适用同一契约，不能把下游关闭误等同于立即关闭上游。
- E10：warmup、生成、后台执行不能混用生命周期或默认假设免费；只开放有独立契约和验收的模式。未知终态不能伪造成成功。I22 的 priming 使用同一准入/finalizer 责任，以内部主体记录，丢弃输出不代表免费或无需结算。

运行 owner 与依赖位置见 [ownership](../../architecture/ownership.md)，能力与重试规则见 [protocol](protocol.md)。

## E11：最小持久执行命令

执行协调在准入前同步取得最终化 ticket；准入原子写入 dispatch intent、身份、Key 归属、窗口、策略及计价版本和估算预留，再调用一次上游操作。任何无法证明未执行的失败保守归为 unknown，不透明重放。最终化移交不等待连接，worker 失败关闭新准入，由已持久 intent 承担重启责任。

用量证据是以 (attempt, revision) 唯一标识、revision 递增的单 attempt 累计快照，不是可相加的事件。保留范围内相同 revision 的不同内容拒绝；较新证据不可减少已有计数或将 complete 降为 partial，较旧快照不可超过已知新快照。partial/unavailable 保留未知暴露；complete 结算后仍接受可信的较新累计用量，不重复扣收旧快照。金额始终为估算，不等于 token 或订阅余额。

最新累计真相独立保留，历史证据最多保留最近 128 条并持久推进压缩水位；历史容量不能阻止新终态或可信迟到用量入账。水位以内的旧 revision 明确返回 staleEvidence，不修改账本。执行上下文在输出下游前可记录单个有界可信累计快照；后续输出失败、绑定失败或取消仍移交该快照，不用 nil 覆盖已知用量。
