# 重置卡分钟级到期自动使用与有界重试

维护者已批准本方案；行为契约以 [identity I21](../../reference/specs/identity.md#i21重置卡消费的持久幂等与到期-owner) 为基础。

## 目标与范围

提前量改为 leadMinutes（1—10080，默认 1440），retryCount 为额外重试次数（0—5，默认 3），固定间隔一分钟；提前量至少为 retryCount + 1 分钟。管理 API 保留仅 leadHours 的旧写入，拒绝混用；读取同时提供向上取整的旧小时字段。界面以小时和分钟输入，明确展示结果和重试规则。

Runtime 保留每账号一个操作、总四个操作、64 账号与有界提示；每账号至多一个到期时间和一个有界重试状态，一个结构化定时任务在下一分钟内处理到期工作。30 分钟读取列表学习到期时间，设置修订变化立即重算。到点重新读列表，仅 available 且未过期可发送；发送前再次检查时间。重启首次扫描重建，已到期阈值但未过期立即处理。

失败包括列表读取失败、网络/超时/5xx 和 unknown，最多初次加 retryCount 次，间隔至少一分钟；已知到期时间截断预算。unknown 始终沿用持久请求 ID；reset/already_redeemed/no_credit 结束重试。nothing_to_reset 不扣失败预算，下个常规周期可再尝试。每次失败/消费沿用有界审计，耗尽后提醒及尝试次数；手动使用无自动重试。关机取消并等待定时器、网络和关键收尾。

## 数据与回退

不升级 schema；account_reset_credits.record_json 仍限 4096 字节。旧设置按 leadHours * 60 和 retryCount=3 解码；新记录同时写 leadHours=clamp(ceil(leadMinutes/60),1,168)，允许 v0.26.4 解码回退。回退只能按小时调度且没有本次分钟重试保证。重试调度和已学习列表不新增持久化；现有 intent/失败计数保留未知执行屏障。

## 排除项

不改变手动使用、提供者内部重试、恢复自动关闭规则或真实订阅验证；不访问部署或真实提供者，不构建 Linux 镜像。

## 验收

注入时间覆盖分钟边界、提前量与预算约束、精确唤醒、重启逾期阈值、过期禁止、失败间隔/预算/同 ID、终态停止、nothing_to_reset、到期截断、耗尽提醒及取消。存储验证旧记录与旧二进制字段兼容，真实合成 socket 验证 API/CAS；前端单元与桌面/窄屏浏览器覆盖表单。运行文档、前端全检查及最终一次完整 macOS 后端检查。结果归纳 I21 后删除本目录，由 Git 保留过程。
