# 管理台前端基础层

日期：2026-10-31。用户决定保留 Mantine，先补齐基础层，再做交互改进。修改前端组织方式，不改管理 API、权限、CSRF、会话与 CSP 契约。

## 问题

Mantine 9、TanStack Query、zod 本身成熟，但页面之上没有共用层，每个页面各写一套：

- Key 与账号各自手写约 250 行修改状态机（忙碌、取消、409 冲突、会话失效），未用 Query 的 mutation；
- 5 个 Modal、5 个 Drawer 各自处理，4 个文件重复同一背景滚动锁技巧；
- 4 个页面共 46 处表格代码，各自实现窄屏卡片、空/加载/错误状态，无排序和列显示；
- 733 行全局 CSS、CSS Modules 与组件属性三种写法混用，无集中主题，难以做深色模式；
- “不可用”、错误提示、时间（本地/UTC/相对）格式分散；趋势图为手写 SVG；主要页面 500—770 行。

## 约束

- 管理入口 CSP 为 `style-src 'self'`：禁止 `<style>` 注入。Mantine 运行时 CSS 变量注入因此关闭。主题须在构建时生成静态 CSS（由同一 theme 对象生成），不放宽 CSP。React 经 CSSOM 设置的样式属性不受影响。Mantine 默认滚动条补偿会通过 react-remove-scroll-bar 注入 style；Key 弹层关闭该补偿，保留 Mantine 滚轮/触摸隔离，以静态 CSS 隐藏背景滚动，不降低 CSP。
- 只为已有两处以上实际使用的模式建共用件（[布局约定](../../development/layout.md)），不预建未来抽象。
- 不改变外部行为与可访问名称；现有 vitest/Playwright 作为安全网，迁移页面增加截图基线。

## 方案

1. **主题与外框**：`app/theme` 集中颜色、字号、圆角、间距与组件默认值；构建脚本生成静态主题 CSS（含浅色/深色两套变量，深色本阶段不开放切换）。外框与页头（标题、说明、操作区）组件化。
2. **反馈**：全局通知（`@mantine/notifications`）替代修改成功/失败的页内提示；确认类操作统一用 Mantine 模态管理，移除手写滚动锁。
3. **数据层**：Query key 工厂；共用 `useManagedMutation` 统一 CSRF、取消、409 冲突刷新与提示、401 会话失效、成功通知；Key/账号修改迁移到它。
4. **展示组件**：`DataTable`（列定义、客户端排序、空/加载/错误状态、窄屏卡片，基于 Mantine Table，不引入表格库）；`StatCard`、`StatusBadge`、`EmptyState`/`ErrorState`、`DetailDrawer`；`TimeText`（本地/UTC/相对，统一“不可用”）、`MoneyText`、`TokenText`。
5. **图表**：采用 `@mantine/charts` 替代手写趋势 SVG（确认其样式以静态 CSS 提供且符合 CSP）。
6. **样式**：全局 CSS 只保留基础与外框，其余迁入组件 CSS Modules 或主题。

## 视觉方向（2026-10-31 用户选定）

经三套渲染图比较，用户选定“C 结构 + A 克制”：

- 结构：左侧浅色导航栏（图标 + 文字，退出登录在顶部右侧）；页头为标题、一句说明与右侧操作；首页 KPI 卡片带图标、数值、较昨日与趋势填充，右侧固定订阅额度卡片；账号页为账号卡片 + 右侧详情抽屉；Key 到期以彩色状态标签加日期展示；用量页筛选收为一行并提供 24 小时/7 天/30 天快捷范围。
- 视觉：保持深绿主色；细边框、轻阴影或无阴影、适度圆角，避免多余装饰。
- 深色运维风格作为以后的深色模式，复用已生成的深色变量。

渲染图仅作方向参考，字段与文案以规范和实际接口为准，不展示接口没有的数据。

## 阶段

- 阶段 1：主题生成、外框/页头、通知与模态、数据层、DataTable 与状态/时间组件；**Key 管理页**作为试点完整迁移。
- 阶段 2：用量、首页、账号页迁移（账号页待“提前刷新”合并后），图表替换，清理全局 CSS。
- 阶段 3：深色模式开关与具体交互改进（按用户目标另提）。

## 验收

- CSP 不变，浏览器控制台无 CSP 违规；主题来自构建生成的静态 CSS。
- 迁移页面：现有 E2E 全部通过（仅允许因通知替换页内提示而调整断言），1440×900 与窄屏截图与迁移前一致或经评审认可的改进。
- 修改流程：409、401、网络失败、取消、成功各有测试；不在缓存保存一次性秘密。
- 删除被替代的重复代码；页面文件明显变小。
- 执行者 `verify.sh --web --chrome` 通过；主 Agent 评审、subagent 界面评审与浏览器走查；Linux verification。
