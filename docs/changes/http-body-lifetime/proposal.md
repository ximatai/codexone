# Responses HTTP 正文生命周期

Responses HTTP 在选择 HTTP 上游且发送结束后，释放请求正文及其预算租约。压缩协商保留原编码直到确认无需明文重发，收到响应头不等同于上传结束。交换提前结束时，发送方先清空编码正文，使尚未结束的传输迭代器无法继续读取，入站请求再归还仍持有的租约。将发送所需正文和响应阶段的小型元数据分离，保留现有准入、发送字节、超时、账本及单次回退语义。

正文生命周期调整覆盖入站 HTTP 且直接使用 HTTP 上游的 Responses 请求，含超限预路由。原生 WS、WS 已派发后的回退、独立 compact 和原生 Images 继续使用原生命周期。回退版本恢复响应结束时归还正文预算。

共享正文容量不足时，已认证的普通 HTTP 已知长度大请求（超过 8 MiB）每个 Key 只占一个等候位置，重复申请沿用 `503 capacity_exhausted` 和 `Retry-After: 1`。已经获得容量的请求继续运行，容量充足时同一 Key 可以同时上传多个请求。保留全局四个位置、五秒期限、接纳后的 FIFO 和小请求余量。chunked、原生 WS 和控制入口维持现有申请方式。此变更无配置、schema 或迁移要求，回退恢复原队列规则。边界见 P26。

复用现有混合容量夹具。第一笔上传后持有上游响应，另一枚 Key 需要共享预算且应能在第一笔结束前派发。保留夹具现有取消、恢复及内存门禁。排队规则在既有 Swift 预算套件验证单 Key 重复申请、其他 Key 入队及取消后恢复资格。

## 加密暂存接入

对启用暂存的已认证 HTTP Responses 已知长度大请求，接收期间用独立磁盘额度接收加密分块。正文完整后用现有共享内存额度解密和校验，沿用请求解析、模型权限、协议改写、Core 准入和账本。直接 HTTP 上游或预先选择 HTTP 的路径可重新把已校验的发送正文存成加密分块，在释放内存额度后派发。原生 WS、compact、Images 与未知长度请求仍用现有路径。

临时文件私有且打开后立即解除目录链接，使用只在进程中存在的随机密钥和认证加密，磁盘挂载策略仍按部署原则管理。支持同一份编码正文的单次 415 重发，保留发送 EOF 与最终编码的交接条件，取消、拒绝或读取错误回收配额。进入低磁盘水位时拒绝新增暂存，不借用账本的磁盘余量。默认关闭，由受信启动配置显式启用。无 schema 迁移，关闭开关可回退至现有大正文路径。
