# Responses HTTP 正文生命周期

Responses HTTP 在选择 HTTP 上游且发送结束后，释放请求正文及其预算租约。压缩协商保留原编码直到确认无需明文重发，收到响应头不等同于上传结束。将发送所需正文和响应阶段的小型元数据分离，保留现有准入、发送字节、超时、账本及单次回退语义。

正文生命周期调整覆盖入站 HTTP 且直接使用 HTTP 上游的 Responses 请求，含超限预路由。原生 WS、WS 已派发后的回退、独立 compact 和原生 Images 继续使用原生命周期。回退版本恢复响应结束时归还正文预算。

共享正文容量不足时，已认证的普通 HTTP 已知长度大请求（超过 8 MiB）每个 Key 只占一个等候位置，重复申请沿用 `503 capacity_exhausted` 和 `Retry-After: 1`。已经获得容量的请求继续运行，容量充足时同一 Key 可以同时上传多个请求。保留全局四个位置、五秒期限、接纳后的 FIFO 和小请求余量。chunked、原生 WS 和控制入口维持现有申请方式。此变更无配置、schema 或迁移要求，回退恢复原队列规则。边界见 P26。

复用现有混合容量夹具。第一笔上传后持有上游响应，另一枚 Key 需要共享预算且应能在第一笔结束前派发。保留夹具现有取消、恢复及内存门禁。排队规则在既有 Swift 预算套件验证单 Key 重复申请、其他 Key 入队及取消后恢复资格。
