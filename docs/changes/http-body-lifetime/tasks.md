跟踪正文释放条件与合成验证结果。

- [x] 分离正文和响应元数据，按实际上传写明归还条件。
- [x] 调整现有混合容量演练中的等待断言并检查压缩、取消、账本。
- [x] 限制单个 Key 占用的大 HTTP 等候位置，验证容量并行、跨 Key 排队及取消清理。

2026-11-19，macOS arm64 构建和 22 项定向 Swift 测试通过。既有三轮混合容量夹具改为在第一批请求仍等响应时验证另一枚 Key 的 9 MiB 请求完成，全程保持 30 次上游派发及原账本断言。既有 zstd 矩阵通过，含早到响应头、完整及提前 415 协商、取消。既有 WS 大小边界全量矩阵两套契约均通过，容量争用夹具改用仍在读取正文的请求保留容量保护验收。无新增 CI 入口或演练轮次。原生 Linux amd64 RSS、cgroup 及完整 60 秒恢复窗口仍由现有发布容量检查验证。

所有权复核后，请求正文保持不可变，响应事件与用量处理只接收 `ResponseOutputContext`。HTTP 派发一次性取走待编码正文，上传结束且编码协商完成后丢弃编码字节并归还租约。415 明文回退在同一次状态更新中重置上传结束标记并确定最终编码。macOS arm64 上复跑既有 44 项定向 Swift 测试、三轮混合容量演练、zstd 矩阵及两套契约的 WS 1009 失败路径，均已通过。

2026-11-19，macOS arm64 上 32 项正文预算、控制容量、期限和 zstd 定向 Swift 测试及既有三轮混合容量演练通过。仅在既有预算套件增加一项同步回归，验证同一 Key 可并行获得空闲容量、只占一个大请求位置、小请求可用独立余量，以及取消后按 FIFO 重新入队。临时回环 HTTP 验证了已认证同一 Key 重复入队实际返回 `503`、`Retry-After: 1`，关闭占用连接后另一 Key 可读完 9 MiB 正文并进入解析。无新增 CI 入口。

整体复盘收敛了上传初始化、HTTP 编码协商和容量夹具中的重复代码。macOS arm64 复跑 40 项定向 Swift 测试、既有 zstd 矩阵、两套契约的 WebSocket 完整边界、三轮混合容量演练，均通过。415 的重发仍使用同一份编码字节和原执行准入。
