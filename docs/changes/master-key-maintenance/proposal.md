# 主密钥多版本维护与可恢复再加密

依据 O03/O04/O09/O10，保留 v1 AAD/信封与现有单 hex 主密钥文件兼容，独立私有 secret 可声明一个 active 和最多七个 decrypt-only；只有 active 写入，按信封 key ID 解密。所有密钥均检查管理员/数据 Key 复用，配置严格有界且脱敏，不写入核心库。

离线命令与服务/迁移/恢复共用实例锁。再加密先验证当前密文并生成独立完成备份，然后按小页事务、密文/context CAS 和追加检查点推进；不修改 credential version、刷新 intent、账号授权或执行真相。检查点与页写同事务，中断目标普通启动拒绝，显式续作必须匹配原 active；完成前复核全部当前密文。复用维护审计表，schema 升至 v8，防旧 v7 二进制绕过再加密门禁；旧 v1—v7 须显式迁移，旧 v7 完成 bundle 可显式恢复并升级，信封格式不变；记录有容量上限，不自动删除责任。

备份 manifest 记录实际密文引用的 key ID 集合，验证/恢复支持混合版本及只读旧备份。退役检查使用候选 keyring、私有完整保留备份清单和对应恢复演练目标；逐一验证当前库、完成 bundle 与演练恢复来源/解密依赖；迁移前原始 v7/v8 SQLite 备份亦须列入并验证依赖，其独立副本恢复演练由外部审计引用明确证明，工具不冒充自动验证，审计只记录 ID 和非秘密外部引用，不输出路径。清单完整性和明确销毁旧备份由操作者承担，系统不能扫描未知外部副本；更早原始 schema 需先独立副本迁移至可验证格式，未验证时不得退役，也不自动删除 secret。

验收覆盖 legacy→多版本读取/新写、错误/重复/过多/不安全配置，未知 key/AAD/篡改拒绝，在线锁、缺失旧 key、错误 active 续作、页事务失败与真实 SIGKILL 后续作，旧快照解密/恢复及退役依赖失败；不真实调用账号，不部署。主 Agent 亲自实现和定向测试，提交后集中 review、修复与阶段出口跨平台验证；Desktop、真实订阅、M5 及低磁盘完整分级保护保留。
