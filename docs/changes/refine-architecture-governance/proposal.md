# 架构与文档治理收敛

日期：2026-10-21。来源：独立结构审查及用户对单一状态入口、可调整业务草案的补充。

## 目标

进度只在 STATUS 维护，README/交接/目录说明只保留稳定职责和链接。业务与技术方向作为可演进工作假设；遇到困难或更好方案及时沟通，不能用“已经确定”阻止提案。将详细行为契约归入规范，架构聚焦组织和取舍，落实审查 R1–R7。

## 范围与非目标

调整文档和占位目录、明确 owner/事务/协议/缓存资源边界，提出可验证恢复契约草案；改进文档检查。不开工实现后端/前端，不开放公共恢复 API，不声称客户端已兼容，不调用账号/改动 Ali/推送。

## 验收

README 无当前实现/测试/远程状态；其他稳定入口不复制全局进度。规范、架构、ADR 明确可提案修订。执行/身份/缓存安全细则有规范归属。恢复草案列出具体关联、输出和失败规则，M3 出口要求至少一条真实可用路径，未经验证不能发布承诺。目录按少量计划 targets 组织，检查器不固定业务目录、活动任务名或扫描依赖产物。

## 数据与回退

只有文档、脚本和 .gitkeep 迁移，无服务数据/schema 变更。保留历史提案/评审与实验快照；需要撤销时可用本变更 Git diff 核对，不覆盖无关工作。
