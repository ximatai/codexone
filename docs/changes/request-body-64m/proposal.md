# 请求正文支持 64 MiB

维护者确认将数据请求上限由 32 MiB 提升至 64 MiB，以支持大上下文。Nginx 入口同步为 65m，保留网关最终判定与结构化 413。单消息上限、分片聚合与下游请求队列一致到 64 MiB；队列拒绝无法容纳的单消息，避免永久等待。

共享正文预算仍为 64 MiB，另有 8 MiB 小请求余量。满额请求独占共享池，其他大请求沿已有最多 4 个等待者/5 秒后 503 的机制处理。保持取消、lease 回收、未知责任与不自动重放。上游原生 WS 12 MiB、单图 16 MiB/总图 24 MiB、控制接口及上游响应大小不扩大，不改变读取和执行期限。

验证复用边界、WebSocket、真实 TLS 与混合容量脚本，覆盖 64 MiB 成功、超限拒绝、小请求可用、取消和重复回收。3 Mbps 出网下 64 MiB 未压缩传输约 179 秒，采用合成慢上传验证首响应期限从 EOF 开始。Linux 768 MiB 容器容量演练必须成功后再发布，真实提供者是否接受此大小仍有独立边界。

无需 schema 迁移或新增热配置。部署时更新模板并 nginx -t/reload，升级保留完整备份。回退旧程序恢复 32 MiB 边界，不更改既有账本。
