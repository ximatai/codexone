# 安全核心备份、旧快照维护态与额度基线

依据 O03/O04/O09、I/U 执行责任，落实离线一致性备份 → 全新私有目录恢复 → restored_unreconciled → 审计基线/冻结受影响 UTC 日窗口 → 新窗口准入。主 Agent 实现、定向回归，闭环提交后集中 review，阶段出口跨平台验证。

备份与迁移/服务共用实例锁；SQLite Backup API 导出核心库，独占私有 bundle、完成 manifest 最后发布，完整性/摘要/schema/单主密钥依赖核对。恢复只接受已完成的当前 schema bundle，拒绝已有目标库/侧车，不覆盖当前服务；旧库先在独立副本显式迁移再备份。manifest 提供完整性和来源标识，不替代受信私有备份来源。

恢复持久记录快照时间、恢复时间及可能缺失区间；所有发送 intent 保留 unknown，旧对象绑定清除以防已丢失的远端上下文误续接，所有恢复 Key 验证材料失效且禁用、账号需重新授权，历史账本与审计保留。旧 schema 普通启动拒绝，升级 v7，防旧二进制忽略维护门禁。

管理员必须提交匹配 restore ID、有限的非秘密审计引用、缺失未结数量/金额及冻结截止时间。截止时间至少恢复日下一 UTC 日；旧窗口不重新接单。缺失未结占用与快照内 unknown 分开保留、跨窗口不自动释放，保守施加于准入容量；没有显式基线不 ready。旧 Key 不复活，后续显式换发新 Key/重新授权账号。审计基线带 CAS 版本和追加历史，新证据可显式修订当前总缺失占用，首次不能低于已继承的缺失占用，不缩短冻结期。核对是管理员基于外部证据作的责任声明，不能从快照推断缺失执行为零；记录零也必须显式审计。恢复旧库不冒充无损回退。

CLI 提供 backup/restore/status/reconcile，可在维护态保留管理查询。仅合成数据、临时目录与上游验证，含 SIGKILL/部分写、坏备份、锁冲突、错误密钥、重启门禁、错误核对 ID、窗口冻结及丢失未结占用。不自动部署/调用真实账号；Desktop、真实订阅、M5、密钥轮换与低磁盘完整分级保护仍保留。

集中 review 修正：恢复时间在复制及复核后记录；首次审计冻结至核对日下一 UTC 日，避免跨午夜提前放行。恢复库拒绝旧静态单身份配置，必须转托管 Key/账号池。复制前同步新目标的父目录；同步失败拒绝发布，注入故障测试不代替掉电验收。
