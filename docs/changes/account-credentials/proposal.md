# 账号凭证与刷新持久屏障

## 目标与边界

推进 M3 的 I06/I08：先交付可失败、可重启验证的凭证认证加密及账号刷新状态，再将提供者授权、Runtime 单飞和路由接上。每个切片独立验证，不把密码学 round-trip 或合成刷新当真实账号接入完成。已有 Key 界面与 M2 两项缺口不变。

凭证使用已锁定 Swift Crypto 的 AES-256-GCM。主密钥由独立私有文件注入，不写核心数据库；密文有格式版本与 key ID，AAD 绑定用途、identity、namespace 和 credential version。密文跨账号/版本替换、损坏、未知格式或错误主密钥均拒绝。文件读取遵循现有类型/owner/权限/容量检查，不自动生成可能丢失或覆盖的密钥。首个切片只持有一个当前主密钥，轮换/备份恢复不得隐含支持。

核心原子命令保存安全账号元数据、版本化密文及 refresh_intent。开始旋转刷新先持久 intent，使账号不可选；成功提交新密文、credential version CAS 与完成标记必须同事务。失败、取消或响应后的本地提交失败不能再次自动使用旧 refresh token。重启在开放路由之前把未完成 intent 归纳为 auth_uncertain。账号身份不能原地改义；不同提供者稳定身份要新建并排空旧身份。

提供者身份与导入材料分开：未验证的本地 JWT 声明不能直接成为 ready 账号。后续适配器仅从可信固定认证端点的授权/刷新响应或可验证身份接口确认等价性；缺失/冲突时失败关闭。公开 Codex 源码仅帮助核实 wire 事实，不作为网关架构或恢复策略。所有开发与故障测试用合成材料，不读取个人登录文件或发真实刷新/生成请求。

## 验收与后续

先验收真实加密及文件边界、SQLite CAS/事务部分失败、持久 intent 前后 kill/restart 与历史 Key/执行不变；再验收有界 Runtime 单飞（等待者取消独立）、提供者差异和管理操作，最后扩展账号池调度。测试只证明各已接入入口，状态按实际出口维护。

新增 schema 需显式离线迁移、同目录一致性快照及实例锁；旧版普通启动拒绝新库，不能静默降级。文档分别披露主密钥、核心库与版本的备份依赖；不把删除凭证当删除历史绑定或账本。

## Runtime 单飞的下一切片

Runtime Service 拥有共享刷新，按 identity 合并相同 revision 的等待者；不同 revision 明确冲突，不静默接受过时管理条件。最多 16 个身份工作、64 个等待者、每身份 16 个等待者、4 个并行提供者调用；容量在加入队列/创建任务前取得。等待者取消只释放自己的等待配额，不取消共享刷新；全部离开也仍由 Service 负责收敛已开始工作。

共享网络调用有总期限和结构化取消。优雅关闭先停接收，未开始的队列不得再消耗刷新令牌；已开始的网络工作收到 owner 的关闭信号，取消并 await，然后持久 uncertain 或留下原 intent。不能为排空队列在现有五秒关闭窗口内继续发新网络请求。提供者端口必须响应取消，后续真实 socket 适配要验证，不能只用一个无法取消的 continuation 声称关闭有界。Runtime 不依赖 Adapters，由入口注入 Core 凭证用例与可信刷新端口。

## 可信认证 HTTP 适配的下一切片

固定可信认证 authority，生产只允许 HTTPS；仅测试工厂可用显式 loopback 合成服务，不新增可把真实凭证发送到任意 HTTP URL 的运行配置。专用 AHC client 禁止重定向及自动重放 token POST，整次请求（含响应正文）有期限、正文有容量，独立限制并发并由 Service 关闭。真实 socket 验证重定向目的端未收到凭证、头/正文拖延、过量/畸形响应及取消后的连接释放。

授权码路径使用 PKCE 与预期 nonce，由后续管理授权流程持有 state/期限/一次性消费；不以任意上传 JWT 作为已验证账号。只从固定 token endpoint 的可信直接响应建立身份，校验 issuer、ID token audience/nonce/有效期及稳定 subject/account 范围，namespace 绑定数据 origin、协议与认证 realm。刷新须比对已有可信身份和新 access token 的相同范围；新 ID token 若提供也须一致。缺少可确认范围、冲突或过期不自动发布 ready，不猜测身份等价。

官方认证文档说明登录与自动刷新，但不提供该底层 token wire 的长期兼容承诺；实现与合成证据须明确区分真实订阅验收。不会读取个人登录缓存或调用真实认证服务来补齐此处证据。账号管理与真实授权仍按后续可操作切片验收，不把 HTTP 200 或解析成功当账号池交付。

固定认证端点明确返回已识别的无新 token 授权拒绝（invalid_grant、已撤销/过期/重用的刷新令牌）时，将结束状态写为 requires_auth；网络/畸形/身份不符或其他不明结果仍为 auth_uncertain。两者都结束本次持久责任、禁止自动再用旧令牌，只有重新验证授权才能 ready；不把所有认证错误混称为未知，也不根据任意服务器 prose 决定状态。

## 初次授权 owner 切片

Runtime 管理最多 8 个授权流程（含最多 4 个正在交换/持久化的流程），10 分钟单调时钟期限；state/nonce/verifier 仅驻留内存并绑定管理 session 的不透明 owner 标识。初次创建使用随机内部账号 ID；重新授权绑定既有 id/revision，最终仍走 Core namespace/CAS，不允许更换账号身份。回调只接收固定 localhost callback 的完整 URL，禁止用户名、密码、fragment、重复或未知参数（可忽略有界 scope）；校验 state，消费流程在 token POST 之前完成，任何失败均不恢复旧流程或自动重放。远程管理可在后续界面粘贴浏览器回调地址，不要求网关占用操作者机器的 callback 端口。

完成调用的结构化任务拥有交换，最长 30 秒总期限；请求取消会取消该调用，Service 关闭向全部在途交换发送停止信号并等待持久化责任收敛，不创建无人等待的后台任务。停止后不得开始新的凭证持久化；已经开始的原子写入允许收敛。初次失败没有已接入账号，不凭失败声称账号 ready；重新授权失败保留原身份与版本。验收覆盖 owner 隔离、容量、期限、消费后重放、取消/关闭、身份变化和持久冲突；此切片不宣称公开 API/UI 已可用。

## 管理与生产组装切片

可选独立 CODEXONE_ACCOUNT_MASTER_KEY_FILE 需数据目录和独立管理员认证，配置校验只加载/核对文件而不打开数据库或发网络请求。主密钥不能复用管理员 secret 或数据 Key。入口组装固定生产 OAuth Service、授权 owner 与共享刷新 Service；所有合成验证只通过测试依赖注入，不引入任意认证地址环境变量。

账号管理复用已有管理员 Bearer 或安全 session/CSRF/Origin，授权 flow owner 取已认证管理域的不透明标识，不能由 JSON 指定。公开列表/模式/刷新/授权响应只返回安全元数据；初次创建和重新授权通过一次性流程完成，不提供 token/JWT 上传或导出。GET 列表有界分页，模式/刷新均带 revision。错误只返回安全代码，状态不明时要求读取核对，不自动重放 mutation。新增界面从用户操作验证接入、取消/失败、冲突、禁用和重新授权；真实账号调用仍需单独授权。

管理 HTTP 完成请求断开后，Vapor 已接收的用例可继续收尾；这不等同 Swift 任务收到取消。授权 Service 仍跟踪该工作，关闭时取消/等待。补实际连接断开后同一授权仅交换一次并持久完成的证据，管理员应读取列表核对，不能凭断开认定回滚或自动重发。


账号界面切片只保留 session/流程信息于页面内存，回调输入为密码类型、提交前即清除，离开页面清除本地信息。接入/重新授权采用新窗口和手工回调，不自动访问操作者 localhost 服务。流程过期需重新发起；请求结果未知或 CAS 冲突先锁变更，成功读账号列表后才能继续。界面分别显示授权与使用策略，invalid_grant 引导重新授权而非重复刷新，登出失败保留明确重试。采用测试专用 ExecutionProbe 组装真实 Runtime/API/合成 OAuth，生产入口无替换 authority 参数；真实 Chrome 验证及大屏截图只含合成材料。

界面 review 补充：登出意图一旦发出即清本地账号/CSRF/提示与流程；未确认前单独显示重试登出，不允许通过读列表恢复管理变更。重试先读取当前 session 证明，401 可确认已退出；其他失败继续封闭。重新读取账号须先同步当前 session/CSRF；其他标签页替换 session 时清除绑定旧 owner 的本地授权流程，避免一直使用旧证明或把旧流程交给新 owner。
