# 治理姿态对齐：可用性优先，保护订阅账号

日期：2026-10-31。修改共识决策“兼容优先用量治理”，以及[用量](../../specs/usage.md) U02/U06/U07/U08、[运维](../../specs/operations.md) O14 容量、[管理面](../../specs/control-plane.md)提醒。取代此前“执行记录保留与容量余量”草案。

## 风险姿态（用户确认，2026-10-31）

- Key 持有者是自己与信任的亲友/同事；限额用于防误用，不防作弊。
- 用量与费用数字用于观察、心里有数，不对外结算；估算或少量缺失可接受，但必须标明，不记零。
- 服务可用与账目精确冲突时，更不能接受停服。
- 真正稀缺、需要保护的是订阅账号的窗口额度，以及账号不因异常使用模式触发上游风控。

## 原则

1. 记账不确定性与观测类上限永不阻断正常准入；只告警、可追溯。
2. 阻断只用于三类：管理员为某个 Key 显式配置的限额、保护订阅账号的流量整形（每账号并发等）、存储与数据安全。
3. 每个持久实体有完整生命周期与保留策略；每个上限写明保护对象、作用范围、时间窗口、到达后的降级方式与余量观测。
4. 影响范围最小化：任何单个 Key 的行为不能让其他 Key 停服。

## 行为

### 未结执行

- 从准入中移除全局与身份范围的未结数量和未结金额检查（含试运行加固的 1024 上限）；Key 维度仅在管理员显式配置时生效。
- unknown 设核对期 24 小时（命名常量）：期内收到迟到证据按实际结算；期满仍无证据，转为终态“已关闭·用量未知”，不估算、不记零，不再计入在途/待核对。统计中继续显示“用量未知 N 条”及原因分布（客户端取消、上游断开、超时等）。
- “核对并释放”保留为管理员提前关闭的操作（带审计），语义同期满关闭。
- 首页提醒：unresolved 改为观察质量提醒——最近 1 小时“非客户端取消”的未知占比 ≥ 20% 且至少 10 条为 warning（可能是上游协议或用量缺失问题），不阻断。

### 全局观测上限

- 全局每日请求数与每日估算预算不再阻断准入，改为观测阈值：达到既有数值的 80% 为 warning，超过为 warning 并标明“已超过参考上限”。

### 保护订阅账号

- 窗口额度：保留 `quota_high`；新增“最近 5 小时窗口用量按 Key 排名”，提醒中指出主要消耗来源，由管理员决定是否禁用或给该 Key 配限额，不自动拦截。
- 风控：每账号并发上限保留为阻断项（默认 16，有命名常量），超出返回可重试 429；新增 24 小时峰值并发观测，峰值 ≥ 80% 时提醒；新增每账号请求速率突增提醒（最近 10 分钟请求数 ≥ 过去 7 天同时段中位数 5 倍且至少 60 条），只告警。

### 执行记录保留

- 已结算或已关闭、且早于 90 天的执行，连同证据与绑定，由 Runtime 维护 owner 小批汇总进按 UTC 日 × Key × 模型 × 模式的日汇总表后删除明细；在途与核对期内记录永不删除。汇总保留请求、各终态与失败分类计数、各类 token、图片数、估算费用与“用量未知”计数，缺失不补零。
- 用量日序列和 Key“最近使用”在明细已清理的日期读汇总；界面说明仅保留最近 90 天明细。
- 对象绑定（续接定位用）单独保留：仅用于短期续接，按既有续接期限过期后由同一 owner 小批删除，不随明细保留 90 天；过期绑定不得影响仍在核对期内的执行。
- 清理后回收空间：库启用增量回收（incremental auto_vacuum，迁移时一次性设置），每轮清理后按空闲页比例小步执行 `incremental_vacuum`，避免文件只增不缩；存储压力 blocked 时暂停。
- 移除 attempts 10 万条硬上限对准入的阻断，改为容量观测（与磁盘水位共同由存储压力机制保护）。
- schema v10（汇总表），按既有迁移流程（实例锁、迁移前备份、事务），旧二进制拒绝 v10。

### 余量观测

- 管理接口返回仍会阻断的上限及当前值：每账号当前/24 小时峰值并发、存储水位；以及观测阈值：今日请求、今日估算费用、明细行数。首页提醒按上文规则。
- 试运行监控读取同一接口。

## 不做

- 用量估算回填、自动禁用 Key、自动降低并发、对外结算级账目。

## 验收

- 未结执行不影响准入（大量 unknown 下仍可准入）；Key 显式限额仍生效；核对期内迟到证据结算、期满关闭、提前关闭审计；统计“用量未知”与原因分布。
- 全局请求/预算超过参考值不拒绝，提醒正确。
- 每账号并发上限 429、峰值观测与提醒；速率突增提醒边界；额度按 Key 排名。
- 绑定过期删除与续接不受影响；增量回收后文件体积随清理下降。
- 保留：迁移 v9→v10 与迁移前备份、批次幂等与中断恢复、在途与核对期内不删、汇总与明细统计一致、缺失语义不变。
- 决策与规范同步（含修订“兼容优先用量治理”）；完整后端与前端验证；主 Agent Linux verification。

## 实现表达与迁移边界

- 关闭状态持久编码为 `state=settled` + `closed_unknown_at_epoch`，API/snapshot 投影 `closed_unknown`；不完整证据仍为不可用/下界，完整证据清标记。v10 使旧二进制拒绝这一新增语义。unknown_since_epoch 从进入 unknown 起计时，旧值按可信结果时间/准入时间/迁移时间初始化。
- usage_daily 按日/Key/模型/模式及结果/失败/完整度/未知维度聚合可空指标；日序列/Key 最近使用合并汇总，小时明细仍只反映 90 天保留数据。汇总不保存对象ID。
- 仓库此前未公布数值续接期限。本实现采用 30 天成功准入/可信绑定续期，旧绑定迁移时获 30 天宽限；这一新增基线已向用户说明，主 Agent 承接时应复核。
- 自动关闭与手动关闭同用 release_unknown 审计并区分 reason；审计保留 90 天，与其他维护操作 1000 条预留隔离，避免自动维护挤占恢复/密钥审计。
- incremental auto_vacuum 需一次性 VACUUM，不能与 schema 改动共处一个事务；先备份再重写、最后事务升版本，schema 失败可重试。空间预算和预计耗时方法见[快照维护](../../development/snapshot-maintenance.md)。
