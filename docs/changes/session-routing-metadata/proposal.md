# 会话路由与协议元数据

同协议透传优先，独立观察治理所需事实，显式处理桥接与续接边界。

## 路由契约

依据 P27/P28、I20 与账号路由所有权。session/thread 只提供 Key 隔离的软位置偏好；thread 可更新自身位置，session/process seed 只首次初始化。保留客户端原意，不从正文缓存键或未经验证的辅助 body 字段推断身份。

提供者实际返回的有界 turn-state 独立记录来源账号，最多 1024 项、一小时单调空闲 TTL，成功查找刷新期限与淘汰顺序（未命中与冲突墓碑不刷新）；只保存 Key 隔离摘要，不保存 token 原文。相同来源重复观察可刷新期限，跨账号冲突标记不可用，不能覆盖为另一个账号。它只约束路由，不授予对象授权或 draining 续接资格。账号池遇到未知、过期、容量淘汰或重启后遗失的 token 返回 503 continuation_owner_unavailable；来源不可选或与对象/连接归属冲突时明确拒绝，不换号、不删 token 重放。可信 single 部署原样传递，不因池内仅剩一个候选而绕过检查。

## 协议与载体

允许有界 session-id/thread-id、OpenAI-Beta、子代理/memgen 标识；凭证、账号、Cookie、门控与逐跳头保持隔离。共享策略位于 Transport。

续接头在原始载体上校验，再做转发过滤；重复、超长或声明为逐跳成员的状态明确拒绝。有效状态在既有 32 个 x-codex 头容量内优先保留，不能因扩展头顺序静默丢失。WS 握手头无效时拒绝升级；首条 create 的状态畸形或与握手冲突时，在 intent 前记录拒绝并尽力发送标准 error 帧。

HTTP→WS 仅把本次请求明确携带的 turn-state 转入 response.create.client_metadata；已有消息字段与头冲突、重复或畸形 token 在 intent 前拒绝。原生 WS 后续消息只读取该消息状态，不从握手补造跨轮状态。HTTP 与 WS metadata 事件接受字符串或非空数组首元素中的有效字符串，沿用有界 turn-state 校验，其他形状忽略，事件其他字段保持原透传；每个有效状态均记录来源，包括 WS 轮次外转发的事件。每个执行首次事件状态用于返回头，后续值不替换本轮返回值。JSON 聚合保留首输出前观察到的状态；SSE 已提交头后不能补头，但继续透传事件。下游 WS 已升级后不补发 HTTP 头，不提前上游连接绕过持久 intent。

## 故障与寿命

辅助 5xx 仅冷却账号/端点，内存最多 1024 项、最长一小时；429 不推测为端点级，继续保留账号级配额保护，401 保留认证屏障。凭证准备完成后在实际选择时重新读取冷却快照，不能把旧剩余秒数跨 await 使用。没有候选时返回适用的 Retry-After，不自动派发重试。

所有新状态归数据服务所有，无后台计时任务，关闭随服务释放；软标签和续接来源各有独立容量。保留强对象/连接授权、结算与未知执行责任。诊断只记录受限类别/网关请求 ID/账号 ID，不记录会话值或正文。

## 验收与回退

合成 HTTP/WS 验证 token 不跨账号、未知/冲突/TTL/容量、逐消息载体与 metadata-only 响应、父子线程 seed、跨刷新冷却、辅助 429/401 和端点 5xx。运行完整后端验收。无 schema 或 Key 格式改变；回退恢复旧软标签及过滤行为。真实提供者缓存率、期限和所有客户端兼容性仍需单独验证。
