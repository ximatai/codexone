# 管理台产品化（第一轮）

日期：2026-10-31。用户要求从产品化、易用易理解的角度迭代管理前端，并且功能不得弱于旧服务的 dashboard。依据是两部分复盘：
- 合成实例的大屏（1440×900）浏览器操作；
- 前端代码、管理 API 与旧服务 dashboard 的对比评审。

## 问题

- **首页**：只有就绪布尔值。看不到可用账号数、今日请求与失败、额度告警、待核对数量和存储状态。旧服务的首页就是额度与用量看板。
- **账号**：
  - 列表只有主窗口已用百分比，没有次窗口（周）、重置倒计时，也没有本地时间；
  - 禁用和排空都是一键执行，没有确认。
- **Key**：
  - 列表缺今日用量、最近使用时间、图片权限、创建时间，也不能搜索、排序或筛选；
  - 禁用没有确认；
  - 编辑器的限额折叠起来但带有默认值，模型没有“全部”，视觉输入与图片生成的区别没有说明。
- **用量与诊断**：
  - 从 Key 跳转过来后需要手动点查询；
  - Key 的筛选和明细只显示 UUID；
  - 明细没有详情，请求 ID 不能复制，没有耗时，没有快捷时间区间；
  - 后端已有的 failed/cancelled、cached、图片 token 细分未展示。
- **术语**：unknown、全时间治理暴露、运营预留、未结、微单位、已准入执行等内部概念直接暴露；金额要用户自己按微单位换算。

## 范围

### 后端（不改 schema 版本）

1. **用量选项与明细带 Key 名称**：`/api/usage/options` 的 Key 项和用量明细行同时返回 `principal`。已删除或未知的 Key 返回 null。
2. **Key 用量摘要**：新增 `GET /api/usage/keys`。
   - 按 Key 返回当日（UTC）的准入数、失败数、估算费用、待核对数（unknown 与在途），以及最近一次准入时间（全时间）；
   - 结果有界：不超过 Key 总上限 256；
   - 沿用用量查询的只读 reader、容量与超时约束。
3. **请求耗时**：
   - 执行结束时，在既有的 outcome/usage JSON 中记录可选成员：首个上游事件耗时（毫秒）与总耗时（毫秒）。只对新记录生效，历史记录为 null；
   - 用量明细行返回这两个值；
   - 不改表、列或 user_version；只观测，不参与结算或治理。
4. 现有接口和字段保持兼容。

### 前端

1. **概览首页**：
   - 未登录时保持现有就绪信息；
   - 登录后增加：可用账号数与授权异常数、各账号主/次窗口剩余与最近重置时间、今日请求/失败/估算费用、待核对数量、存储与准入状态；
   - 每项可以跳转到对应页面；
   - 复用现有接口与新的 Key 用量摘要。
2. **账号**：
   - 列表直接显示主/次窗口剩余比例条（绿/黄/红）和“x 小时后重置”，悬停显示本地时间与 UTC；
   - 禁用和排空前弹确认，说明对在途请求和新请求的影响；
   - 空状态带“发起账号授权”的引导；
   - 授权步骤编号完整。
3. **Key**：
   - 列表增加：今日请求/上限、今日估算费用、最近使用时间、创建时间、图片徽章；
   - 支持搜索主体名、按状态筛选；启用的 Key 排在前面；
   - 禁用和轮换前弹确认，说明影响；
   - 编辑器：限额摘要常驻显示，可以“全部模型”，用 ⓘ 解释视觉输入与图片生成。
4. **用量与诊断**：
   - 从 Key 跳转后自动查询；
   - Key 用主体名下拉选择，明细显示主体名；
   - 增加快捷区间：最近 24 小时、7 天、30 天；
   - 明细行可以打开详情抽屉：完整请求 ID（可复制）、Key/账号/模型/模式、结果与错误说明、用量与耗时；
   - 展示 failed/cancelled、cached token 和图片 token 细分。
5. **术语与单位**：
   - 金额按“估算 $x.xx”显示，限额阈值也按美元输入，底层仍为微单位，换算为 1 USD = 1,000,000 微单位，界面注明“估算，非账单”；
   - “unknown/用量未结”改为“待核对”，“暴露/预留”改为“待核对占用（预估）”，“已准入执行”改为“请求”；
   - 关键术语附 ⓘ 说明；
   - API 契约与后端术语不变。
6. 用量页统一到 Mantine 组件风格；大屏优先，同时保持窄屏可用。

## 不做（需要用户决定或单独提案）

- 账号显示名或备注：需要 schema v9 或新的持久字段。
- 展示账号邮箱或 plan：需要先评估隐私与契约。
- Key 到期时间：改变行为。
- 管理员核销待核对记录：改变治理与结算语义。
- 侧栏导航与深色模式。
- 账号级趋势图。

## 验收

- 后端：
  - 新接口和字段有单元/集成测试：Key 名称连接、删除或未知 Key、摘要上界与时间窗口、耗时只在新记录出现、历史为 null；
  - 管理 API 的认证与 CSRF 不变；
  - `verify.sh --backend` 通过。
- 前端：
  - vitest 覆盖金额换算、术语映射与倒计时格式；
  - Playwright 覆盖：登录后的首页卡片、Key 列表与搜索、禁用确认、从 Key 跳到用量自动查询、明细详情与复制；
  - `verify.sh --web --chrome` 通过；
  - 主 Agent 在 1440×900 下从用户角度走查。

## 实现口径

- 兼容保留 options 的 `keys` ID 数组，新增 `keyOptions`（id、可空principal）；包括有历史请求的已删除/未知 Key，选项总数仍限256。摘要仅包含当前托管 Key，计数窗口为 UTC 当日，最近使用时间为全时间。
- 耗时从准入后执行上下文开始，首事件为解析出的 SSE 事件/WS消息，非流式为完整响应到达；没有首事件时为 null。JSON 可选成员不改变结算。
- “最近24小时”按已完成UTC小时查询，符合后端小时边界；7/30天按含今日的UTC日期区间查询。
- 账号排空沿用现有语义：停止新的会话请求，但保留已有身份关联续接；禁用阻止后续派发。两者均不主动取消已派发请求。
