# 面向协议持续演进的边界设计

将开放协议原则落实为默认行为、局部适配边界与可验证的不变量。本文件为活动提案，不代表当前实现已满足全部要求。

## 目标与保证范围

大部分新增参数、metadata、输出成员与普通事件，应在已有授权操作和资源边界内无需修改网关。改变模型授权、私有引用、执行副作用、生命周期或 framing 的变化必须显式理解，改动集中在对应适配边界；业务事实本身新增时才扩展 Core。

不承诺对所有未来协议零改动。尤其不能从未知内容自动证明“已成功”“有权读取”或“尚未执行”。源码检查、合成差异测试、真实客户端验收分别提供不同证据。

## 三条独立路径

1. **传输内容**：保留原始/有序 JSON 载体、SSE/WS 载荷及未知成员，在既有字节、深度、队列和期限边界内转发。必要改写只发生在明确位置，如可信认证头、默认模型及已验证的订阅传输转换。不构建覆盖完整提供者 schema 的 DTO，不把忽略字段变成丢弃字段。
2. **业务事实投影**：只提取网关必须理解的模型要求、归属、有效进展、已知终态和可信计数。投影不负责重建回传文档；不理解某项事实不意味着删除其原始回传内容。
3. **执行风险**：单独记录提供者是否可能已经处理请求。未知应用事件即使不能证明进度/终态，也可能否定“未处理、可回退或零用量”的假设。不能把“未识别”当“未执行”。

现有 ProviderObservation 附近可先以小型纯函数投影实现这些事实；HTTP/SSE/WS、归属与进度消费相同解释，保留各自连接 owner。优先复用现有 Core 用例，不增加全局调度 actor、事件总线或插件框架。

## 变化分类与默认处理

| 变化 | 默认处理 | 需要改动的边界 |
|---|---|---|
| 已授权请求的新可选字段、工具参数、metadata | 保留，不因不认识而拒绝 | 通常无生产代码改动；加入扩展不变性用例 |
| 已知事件新增成员、当前 turn 的新展示事件/输出类型 | 有界转发；未知语义不授予归属、进度或终态 | 通常只增加证据，不增加运行时格式开关 |
| JSON/base64 封套内的新输出格式 | 不复用输入 codec 白名单；不执行内容，不抓取链接 | 若无需转换则不解码；需要新传输/转换才局部适配 |
| 新 usage 细节 | 回传与内部计量分别判断，不随内部白名单整块删除 | 有界计量投影；未知费率不抹掉已知 Token |
| 新可信终态或有效进展语义 | 未理解前不猜成功或续期 | 对应事件语义投影及测试；一般无需改 Core 状态定义 |
| 新显式模型选择、硬引用或会发起执行的控制 | 不能自动继承旧操作的授权与恢复含义 | Adapter 提取要求；Core 准入/归属规则。无法表达的新业务语义再扩展 Core |
| 新路由、二进制 framing、内容编码或必须解码的输入 | 不从普通未知字段策略推导为已支持 | 对应 Transport/Adapter owner、资源与失败路径验收 |

变化是否引入新责任，是基于协议证据的设计判断；运行时不能靠字段名启发式保证理解所有未来副作用。未知操作与已有操作内的新字段必须区分。

## 未知内容的不同待遇

- **未知字段/普通输出**：可保留，不能仅因缺 DTO case 或本地输出 codec 让提供者已生成的结果失败。若所选路径必须把新形态转换成另一协议，网关仍需理解转换所依赖的事实；优先减少无必要转换。
- **未知事件**：先按已有 lane/response 归属规则隔离旧 turn 与无法确认的消息；能安全交给当前客户端的内容可转发。未知事件不自动产生 bindings、可信用量、有效进展或完成事实。
- **未知执行风险**：无法证明是纯连接元数据的应用消息，应保守影响安全重放判断。明确旧 turn 的消息须继续隔离，不污染当前 turn；未知响应与缺失归属不能被当作纯元数据。
- **计量扩展**：权威总数已经覆盖的新分解明细，不因多一个字段就使全部用量未知；独立新增组件如 svg_usage 未计入整次覆盖度时保留 partial。畸形指标局部不可用，保留其他可信值及既有下界，不因单纯计数异常拒绝合法产物。
- **未知终态/控制语义**：不得靠 EOF、DONE 或名称相似猜完成；未知不构成零用量或重放证据。必要适配只补语义映射，不放宽授权和归属。

转发保留不等于持久保存：Core 仅保存经过验证的有界事实；未映射原因或安全数值证据可有界记录，不保存任意未知 JSON、正文、图片或凭证。新的持久事实另评估语义迁移及回退。

## 近期变化暴露的架构债

- **GIF/SVG 输出**：Responses 使用 ImagePayload 的输入格式校验作为输出门禁，说明责任与 codec 耦合。修复应拆分输入安全检查与输出交付规则，不只是再增加两个格式分支。
- **强制 SSE**：当前 workaround 扩展到未知格式仍可能改变客户端模式。应把转换收窄到有证据的操作/契约，未覆盖形态尽量保留客户端选择；已验证旧路径保持回归，不能全局贸然切换。
- **usage 回传**：ProviderObservation.textOutput 的计量白名单同时决定客户端能收到什么，可能删除新客户端需要的字段。应评估并分离回传保留、已知字段兼容修正、敏感错误脱敏与可信计量投影；不是简单删除所有现有保护。
- **未知事件字段触发语义**：ProviderObservation 因任意事件携带 item/item_id 就提取归属，甚至进入旧图片校验，与“未知事件不授予语义”不一致。需保留已知 content_part 等事件的合法绑定，不能直接删除全部非 lifecycle 绑定。
- **未知事件续期**：ExecutionProgress.note(event:) 对多数 typed 事件都会续期，尚未落实只认已知有效进展；应消费明确事实，保留 first/idle/total 与取消边界。
- **1009 例外**：WebSocketTurns 的 receivedLifecycle 与 response.* 命名启发式不能完整表达处理风险。未知 start、非 response 前缀消息、created 前后的当前/旧/未知 response_id 均须覆盖，避免把不理解当成可安全回退。

上述为静态路径与设计边界复盘，不声明已发生跨账号访问或重复执行事故。

## 如何使保证可验证

普通业务测试之外，加入“协议扩展不变性”回归：

1. 向既有成功请求/响应插入未知字段、嵌套 metadata、输出类型，验证其内容和值保留；只有声明的改写点允许变化。涉及大整数、null、转义及有序 JSON 时，先验证现有载体是否保真，再决定解析改进，避免预先重写解析器。
2. 注入未知事件，验证其可转发时不授予对象归属、进度、终态或额外权限；已知事件增加成员仍正常工作。
3. 对 created 前后、当前/旧/未知 response_id 的未知事件接续 1009，验证归属隔离与安全重放/零用量条件，不只检查“有没有透传”。
4. 连续未知事件、注释、ping、空 delta 不应绕过 first/idle/total 边界；未知“像终态”的事件不结清。
5. 新 usage 明细保留，可信总数与累计 revision 不重算/双算；独立未知计量标覆盖度不足；坏字段不清零其他证据。
6. 相同业务流改变 chunk、WS 分片和慢消费者时序，结果/归属/用量事实保持一致，取消和关闭后资源归还。
7. 同时保留负向测试：模型越权、新私有引用、未知执行控制、非法输入与资源越界继续拒绝。

最低改动目标：新增普通字段无需修改生产代码；新增已知事件语义优先只修改一处 Adapter 投影；新增授权要求按现有 Core 语义复核；真正的新执行/恢复业务才扩展用例和持久责任。

## 发现变化与实施顺序

先复用有界 ClientProtocolExtensionRegistry 的观察方式，记录机器名称、客户端版本/类别及处理结果，不记录值或正文，不自动授权或付费探测。维护固定客户端 revision 的可读源码差异和兼容矩阵；补充当前 image-generation 扩展目录及 Images 请求类型等真实落点，不因路径迁移漏查。当前不新增定时任务。

实施先后：扩展不变性与风险测试 → 小型语义投影和回传/计量分离 → 图片输入/输出及有限传输转换整理 → 跨入口/混合负载验收 → 有授权范围的真实客户端验证。结合[业务设计复盘](design-review.md)推进，不把这份提案当作所有变更已实现。
