# 多 lane 连接关闭的错误交付

定义共享上游关闭时，各 lane 的有界交付、取消与未知责任。

## 问题与边界

合成真实套接字复现：上游已收到两条 1 KiB create 后关闭 1009，两条执行均保留 unknown，但首条 lane 抛出连接关闭会取消其他 lane，客户端可能只收到一个 502。错误日志和已结算账本不能证明下游错误已提交。

## 设计与验收

沿 P03/U06 的连接及未知责任边界，连接 owner 停止接纳新命令，活动 lane 先提交各自错误；已排队但未派发命令只释放资源，不伪造执行。lane 不提前唤醒 Pool 初始 owner 或取消同级任务，由连接关闭监督者在活动计数归零后统一结束。活动计数等候受现有 10 秒关闭期限约束，超时仍取消并回收，持久最终化仍须等待完成；不保证断连客户端收取错误，不自动重放、不改变 unknown、额度或持久 schema。

用两个真实 lane、两种上游契约重复验证：上游恰好收到两条，客户端各收到一次带 lane 的 502 后连接结束，账本两条 unknown；同时回归单 lane 413 后复用、断连、取消、队列积压与关闭期限。
