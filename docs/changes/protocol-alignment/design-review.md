# 业务设计复盘与实施方向

依据现有产品原则评估长期一致性，指导本轮协议与容量实现；本文件是活动提案，不另建立一套行为规范。

## 定位与判断

维护者已确认继续个人自托管、多账号、多设备和工具协作的方向。扩展重点是日常客户端工作流、订阅账号保护、可解释的用量与有限恢复，不引入多人托管、严格收费或多节点调度的假设。

现有 Core 准入/归属/可信事实、Adapters 协议与 I/O、Runtime 寿命监督的分工适合这一定位。需要收敛的是跨入口业务口径及资源边界，不是重建平台框架。

依据：[产品目标](../../requirements/product.md)、[身份 I03](../../reference/specs/identity.md)、[开放协议 P27](../../reference/specs/protocol.md)、[用量 U03—U08/U12](../../reference/specs/usage.md)、[执行 E02/E07—E09](../../reference/specs/execution-lifecycle.md)、[职责](../../architecture/ownership.md)及[可用性取舍](../../architecture/decisions/README.md)。

## 统一业务契约

| 维度 | 应保持的原则 | 本轮及后续设计方向 |
|---|---|---|
| 图片能力 | 一个生成/编辑能力，多个协议入口；视觉输入独立授权 | Images 与 Responses 共用 imageGeneration 和有效图片模型范围；Responses 另需宿主对话模型授权，原生 Images 不借宿主权限 |
| 格式与能力 | 格式属于输出能力与协议参数，不是新权限树 | GIF/SVG 沿图片权限，无独立开关或逐账号格式白名单；提供者决定实际支持，验收证据不冒充运行时授权 |
| 模型边界 | 调用者选择须在准入前授权，不能从模型名推断或自动启用新模型 | 默认 SVG 作者属于提供者完成已授权图片操作的内部实现；显式指定额外作者模型须表达为授权要求。当前客户端证据支持暂拒该选择，但不能以旧客户端 schema 永久冻结新字段 |
| 输入与输出 | 检查应服务网关实际责任 | 参考图/mask 保留有界输入校验；提供者输出有界、不执行、不抓取外链，保持客户端契约。不能复用输入格式白名单决定所有输出是否成功 |
| 输出与用量 | 响应完成、用量完整、价格可用分别是事实 | 成功输出但计量缺失应表达为“响应已完成，用量待核对”，不提示重新生成；单纯计数字段缺失、畸形或越界只使对应指标不可用，不拒绝合法产物。已知作者 Token 须验证并保留，费率未知不抹掉计数，不伪造完整费用 |
| 资源与准入 | 网络接收资源与持久业务准入有不同 owner | 接收容量不授予 Key/模型权限；未建 intent 的等待不算已派发。所有队列有容量、期限、取消和释放路径；不因等待或断线重放 |
| 恢复 | 读取已有结果与新生成分开 | 未来只在实际客户端读取契约成立后引入加密、隔离、限期限量的恢复；计量未明不等于需要再次生成，不默认建设永久图片历史 |

原生 Images、Responses 工具及 HTTP/SSE/WS 保留各自传输寿命，共享必要的授权、输出与用量事实。共用逻辑先放在已有 Adapters 的实际复用位置，Core 不接收 wire DTO，不为每种格式预建服务或插件接口。

## 用户工作流的成功标准

- 同一 Key 在原生生图、对话内图片工具及参考图编辑中获得可解释且一致的图片授权；格式变化不需要重复配置。
- 多设备并发时，能解释请求在等接收容量、图片许可、账号可用还是上游输出；等待本身不生成虚假执行记录。
- 完成图片操作后，客户端拿到符合该入口契约的真实格式数据；计量缺失不把已完成响应暗示为失败或诱导重试。
- 账号、Key 撤销、断流与重启时，归属和未知责任保留，既有内容不跨账号恢复，不透明重放。
- 新客户端/格式出现时，按实际授权与资源责任评估，保持可安全透传的扩展性；未知字段本身不构成拒绝理由。

“响应已完成”只表示网关验证并提交了对应结果，不保证对端已消费，仍沿 P27 的交付边界。

## 计量异常与业务失败的边界

Responses 现有 revision 0 先保存宿主可信计数的做法应保留；工具计数畸形时抛错并阻止结果交付，属于仍需调整的设计债。合法产物与可信完成终态已经成立时，应保留宿主和其他可信指标、降级计量完整度，不能因单纯计数异常把业务结果改为失败。

非法产物、资源越界、协议损坏、提供者显式失败或缺少可信终态继续沿错误路径；计量降级不放宽这些约束。后到畸形证据不得减少或覆盖先前可信下界。新增作者计量及价格可用性的持久化须评估语义迁移与回退影响，不能假定新增可选 JSON 字段天然兼容旧计量/限额逻辑。

## 分层资源地图

| 阶段/容量 | 保护对象与 owner | 需要解释及验证的边界 |
|---|---|---|
| 数据连接 | Transport 连接 supervisor；FD、channel 和任务 | 连接数不是正文总内存上限，控制余量须可用 |
| 全局正文预算 | 数据服务的 lease；本地驻留正文/关联消费者 | 共享 64 MiB，单正文 32 MiB；当前不计入的 ≤8 MiB 正文须纳入混合负载评估，不能据此宣称全 RSS 有界到 64 MiB |
| WS 入站/请求调度队列 | 连接 owner；局部突发 | 每队列保持 48 MiB，独立命名；与全局预算禁止语义耦合 |
| lane | 连接监督的 worker/队列；顺序与并发 | 按连接和全部 lane 的组合占用验收，不能只验证单队列满 |
| 图片许可/账号等待 | 请求 owner；图片活动并发及订阅保护 | 等待时正文可能仍被持有；明确是否已建 intent，计入相应阶段观测 |
| 大图片结果/慢消费者 | I/O owner；有界结果与下游背压 | 48 MiB 原生结果、base64/JSON 处理及取消须共同测量，双大输入＋小文本回复不足以代替 |
| 最终化/未知核对 | Core 事实与 Runtime 有界 worker | 关键收尾容量独立；本地字节对象释放不取消持久责任，unknown 也不使原始正文永久驻留 |

先建立持有对象、释放者和阶段事实，再依据负载证据调整策略。观测使用固定阶段及有界计数/耗时，不采集正文，不为显示等待而提前写生成 intent。

协议层的默认兼容、事实投影、未知降级及演进验收另见[面向协议持续演进的设计](protocol-evolution.md)。

## 跨入口验收口径

| 场景 | Images | Responses JSON/SSE/WS | 账本/边界 |
|---|---|---|---|
| 已授权 GIF/SVG | JSON 真实格式字节；无额外开关 | 图片工具交付真实格式字节 | 图片模型与 Key 范围不变 |
| 未知格式/字段 | 未知格式保留 stream 选择，结果仍须合法封套 | 未知成员/普通事件保留，不要求完整 DTO | 不新增归属、进度、终态事实 |
| SVG 独立作者用量 | root/item svg_usage 保留 | root/item svg_usage 保留 | 已知计数下界 + partial/unknown |
| 畸形计量 | 有效产物不因单纯计数异常失败 | 多图片保留各有效小计，宿主独立 | 不补零、不把部分证据结清 |
| 未知事件后 1009 | 不适用 WS 回退 | 不能证明未处理，不重放 | 多 lane 连接关闭不逐轮结零 |
| 非法输入/越权/超界 | 派发前拒绝 | 派发前拒绝 | 不因为开放输出放宽输入与准入 |

## 实施顺序与发展边界

1. **先收敛契约和验收表。** 固定权限、输出完成、计量完整和容量的含义，按客户端/模型/入口/格式/传输建立最小代表矩阵；不展开未经使用的全部组合。
2. **依契约补齐实现。** 修复 Responses 输出与 svg_usage 覆盖、分离输入/输出校验、拆开 64 MiB 共享与 48 MiB 连接队列；保留已知作者用量及明确的缺失原因。partial 保护是底线，不作为长期计量闭环的完成态。
3. **验证业务闭环和资源组合。** 真正的合成 GIF/SVG 字节；权限/撤销与所有入口一致；大小正文混合、多 lane 等待、大结果＋慢消费者/取消，以及关闭后 RSS/FD/task/lease 回落。用固定阶段观测解释等待和拒绝。
4. **受控真实验收与发布。** 复用已有验收 Key，在明确模型及调用次数后验证真实客户端和账号；候选镜像由 CI 构建，备份、不可变产物核验、观察及回退同时准备。

未来新增策略应由证据触发：小正文/大输出确实突破弱机目标时再完善资源记账；单设备争用明显时再考虑简单的每 Key 接收约束；第二种真实多模型操作出现时再考虑更一般的组件用量结构；恢复契约成立后再建独立恢复存储。

常量解耦、共享事实归一、明确 owner 和补验收属于工程工作。以下改变必须带证据和代价另行确认：小正文全部计入全局预算、交互/批量优先级或每 Key 资源占比、降低并发、允许授权范围外的作者模型、落盘真实内容及恢复保留期限。已确认的个人自托管定位、64 MiB 方向及图片权限边界不重复询问。
