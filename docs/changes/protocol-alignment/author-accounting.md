# SVG 作者用量与发布验收

本轮按已确认业务边界补齐计数、价格与完成事实；实现前的活动设计。

## 计量契约

官方 Images 文档将 svg_usage 定义为独立作者用量，包含 model、input_tokens、output_tokens、reasoning_tokens、total_tokens；公开定义不是当前订阅能力证明。仅解释有界可信计数，不保留原始 JSON 或内容。输入/输出分别保存，reasoning 为输出明细，不重复相加。字段缺失、畸形或来源歧义保留已知下界和固定原因，不阻断合法产物。

根 svg_usage 按整次累计快照优先；没有根时单个图片条目的作者记录可独立解释。多条未确认是否互斥的记录不盲加，保留最大可信下界并标来源歧义；重复 SSE 也不累加同一累计快照。请求明确 SVG 却无作者证据时保持计数不完整。

UsageEvidence.completeness 表示计数覆盖，新增独立 priceCompleteness 表示价格覆盖。作者计数已齐而费率未知时可结清计数，价格为已知下界；没有任何可信价格时返回不可用。价格仅从可信配置的精确模型映射取得，名称观察不授予模型权限、不启用模型。生成成功继续按 outcome 表达，界面明确“生成成功，用量待核对”或“费用为下界”。

用户已确认作者输入＋输出额外计入 Key 每日 Token 上限：保留原有 Responses 宿主／原生图片渲染基数，额外加作者输入输出，不重复加缓存、reasoning，也不顺带改变 Responses 渲染的旧口径。历史不回算。

## 持久与回退

计划 schema v12：保留有界作者事实及价格覆盖度，usage_daily 增加作者计数与价格未知次数，归档前后统计及每日限额一致。旧证据不补作者零值；旧价格覆盖沿历史 completeness 解释。升级需停服备份并显式迁移，旧 v11 程序拒绝 v12；回退需升级前备份，不能用旧程序原库维护新计量。

同步 Core/SQLite 范围验证、revision 幂等/单调性、明细/合计/日汇总/Key治理/估算提示。迁移失败保持事务回滚，恢复与旧库拒绝必须使用真实接口验收。

## 验收与发布范围

覆盖 Native/Responses、根/单项/歧义多项、零值/缺失/畸形、未知模型费率、重复/乱序revision、重启、归档前后聚合、Key上限；UI合成大窄屏确认成功/计数/费用分别表达。

Linux 混合容量使用同一候选镜像，测大输入、小请求、大图片结果、慢消费者、多lane和取消；区分直接资源快照与行为代理，不以线程数代替Swift任务数。候选由CI构建，执行Release dry-run，不从普通Verify推断优化镜像已验收。

真实客户端验收使用既有固定Key，先列明模型、入口及调用次数再确认；不保存真实正文/图片到仓库。首页实时只在前端失败修正及相应容量/失败矩阵完成后随版，较大重做则后发。当前不打正式标签、不部署。
