# 协议容量与图片能力对齐

明确正文容量与扩展图片格式的协议边界、验收和回退。

## 已确认的业务边界

大正文争用共享容量时短时等待，超时返回 503；只等待容量，不重放已派发请求。GIF/SVG 按账号实际确认的能力支持，未确认时明确提示，不能从公开 API 推断订阅内部端点能力。

## 设计与规范影响

- 对照 [协议正文预算](../../reference/specs/protocol.md)及[职责约定](../../architecture/ownership.md)，保留单正文 32 MiB、免预留阈值 8 MiB、共享预算 48 MiB。HTTP 已知长度正文及 WebSocket 首帧在读取大正文前最多等待 5 秒；全局最多 4 个空 lease FIFO 等待者；增量及控制申请不加入该队列。等待仍受原读取期限、取消和连接关闭约束。增量正文已持有部分内容时继续立即拒绝，避免相互持有容量等待。
- WebSocket 等待由连接事件循环拥有，暂停主动读取，已在途输入最多暂存 256 KiB；超出提前返回容量错误并丢弃该消息。超时、断连和移除均释放等待票据，已完成正文的 lease 仍由执行 owner 持有。
- 图片生成不再对非流式格式强制 SSE。扩展格式仅限原生 generation，需要部署配置逐账号、逐模型确认；edits 与 Responses 图片工具的扩展格式未验证，明确拒绝；路由仅选择已确认候选，未知能力在派发前明确拒绝。普通图片现有默认行为保持兼容。
- 诊断只增加固定枚举，不采集正文、密钥或账号身份；不根据断连自动重试。

## 验收

真实传输边界测试覆盖等待后成功、排队上限、超时、取消、断连、在途输入上限、分片增长拒绝及下一消息恢复。图片测试覆盖路由隔离、未确认无派发、格式与流式组合、普通格式回归及用量结算。合成提供者不代表实际订阅兼容；真实能力需另行验证后才配置确认。

## 排除与迁移

不增加内存预算，不实现透明重放、steering 或文件上传新接口，不改变持久恢复屏障，不自动付费探测账号能力。无数据库 schema 迁移；回退前移除新增图片能力配置，等待机制回退为立即 503。线上部署和付费能力探测在本地与 CI 验收后另行准备。
