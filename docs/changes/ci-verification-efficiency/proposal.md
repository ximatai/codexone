# 缩短常规 Verify 的关键路径

常规 main 推送按实际提交范围选择检查。范围不明、强制推送、CI 政策变更与未知路径走全量。main 各次推送独立执行，避免后一次取消前一次差异的验证。PR 保留同一 PR 的旧运行取消。

纯前端路径仍构建同次 Linux 网关并运行真实浏览器联测，Swift 测试与协议脚本由后端变更和手动全量验证触发。手动 Verify 保留全量。发版前用目标 main 提交的全量 Verify 作证，可与 Release 演练并行。发行仍完整验收优化镜像。后端分片根据实测重排，保持全部脚本各执行一次。

隔离浏览器测试和真实网关联测共用固定 digest 的 Playwright 镜像。联测从同次 Swift 构建取得网关及匹配的 Swift 和 SQLite 动态库，先检查可启动，再执行完整联测。

常规 Verify 对仅管理面相关的后端改动，使用真实网关检查超限拒绝、HTTP 路由和上游 1009 后的回退。其余后端路径、未知范围、手动全量、本地默认和 Release 继续执行完整 WS 大请求矩阵。

本次仅调整 CI。回退可恢复 main 的全量默认和原分片，无数据迁移。
