# 局域网模式

拟为没有域名和证书的局域网部署提供显式开启的 HTTP 模式：网关直接监听一个局域网地址，管理页面与客户端用 `http://<局域网 IP>:端口` 访问，不需要 Nginx 或证书。代价是秘密与内容在局域网中明文传输，须在安装、日志和管理界面明确告知。

## 问题

现有安装要求管理 origin 为 HTTPS，并由宿主 Nginx 终止 TLS。家庭或小团队局域网通常没有域名和可信证书，自建 CA、自签证书或 SSH 隧道对多数用户门槛过高。维护者决定：局域网内允许用户在知情前提下承担明文风险，换取简单清晰的配置。

## 方案

### 安装

`init-install.py DIR --image ID --lan 192.168.1.10` 以局域网模式初始化：

- 不需要 `--origin`；管理 origin 自动为 `http://192.168.1.10:18081`，数据入口为 `http://192.168.1.10:18080`。
- 可选 `--lan-allow CIDR[,CIDR…]` 收窄允许访问的来源网段；缺省允许全部私有网段。
- 初始化在终端输出风险说明，并给出管理地址与客户端 `base_url`。
- 与 `--origin` 互斥。切换模式通过私有 `.env` 字段完成，指南给出步骤。

### 网关

1. **监听**：新增 `CODEXONE_LISTEN_ADDRESS`。缺省不变，只监听 `127.0.0.1`。设置后，数据与管理入口同时监听 `127.0.0.1` 和该地址。该地址必须是本机私有地址字面量：IPv4 10/8、172.16/12、192.168/16、100.64/10，或 IPv6 fc00::/7；公网地址、通配地址与主机名拒绝启动（错误码 78，不回显值）。
2. **来源网段**：新增 `CODEXONE_ALLOWED_NETWORKS`，缺省为上述私有网段加回环。非回环监听上的连接按对端地址检查，不在网段内直接关闭，不读取请求、不信任转发头。数据与管理入口都适用。
3. **管理会话**：管理 origin 为 `http://` 且非回环时，session cookie 名改为 `codexone_admin`，去掉 Secure，仍为 HttpOnly、SameSite=Strict、Path=/、无 Domain。其余校验不变：精确 Host/Origin、CSRF、寿命与容量。HTTPS 与回环 HTTP 行为保持不变。
4. **告知**：启动日志输出一行局域网明文模式警告。系统状态 API 标明传输模式；管理界面在每页顶部常驻提示“局域网 HTTP 模式：管理员秘密、Key 与请求内容在局域网中明文传输”，并链接到风险说明。

### 文档

- README 在部署步骤之前给出两条路线：“局域网（无域名）”只需初始化、配置模型、启动、打开管理页面四步；“公网或有域名”沿用 HTTPS 步骤。
- 风险说明写清：同一网络的设备可截获管理员秘密、session、Key 与请求内容；不要在公共或不可信 Wi-Fi 使用；不要用端口转发暴露到公网；需要跨网络访问时改用 HTTPS 或 Tailscale 等私有网络。
- 安装指南补充模式切换与回到 HTTPS 的步骤。

## 不做

- 网关内置 TLS、自动签发证书或 mDNS 名称。
- 监听公网地址或 `0.0.0.0`。
- 放宽 HTTPS 部署的任何现有校验。

## 验收

- **配置**：私有地址通过；公网、通配、主机名、畸形网段拒绝且不回显值。`--lan` 与 `--origin` 互斥。
- **真实 socket**：
  - 局域网地址上的数据与管理入口可用，回环继续可用；
  - 网段外对端被拒，且不读取请求体；
  - 局域网 HTTP origin 下登录、CSRF、登出、Host/Origin 拒绝路径与 HTTPS 模式一致；
  - HTTPS 模式与缺省回环模式的 cookie 和监听行为不变。
- **浏览器**：通过非回环 HTTP 地址完成登录、风险提示展示、创建 Key 的关键流程，检查 1440×900 与窄屏。
- **客户端**：真实 Codex 客户端以 `http://<局域网 IP>:18080/backend-api/codex` 发送 HTTP 与 WebSocket 请求，在测试环境记录日期与版本。
- **数据**：不改变 schema。回退旧版本时，先把 `.env` 恢复为 HTTPS 配置。
