# 上传完成后开始首响应计时

定义上传与首响应期限边界，避免健康的大请求在发送期间过早失败。

## 目标与规范

按本任务约定调整 [协议期限](../../reference/specs/protocol.md)：HTTP Responses 与上游 WS 的首响应等待从请求上传完成边界开始，总执行期限仍从执行开始覆盖路由、连接和上传；首事件后的 idle、取消、未知结算、账号健康与禁止透明重放规则不变。

HTTP 使用已知长度、64 KiB 分块的 Data AsyncSequence，在 AHC 请求序列 EOF 时启动首响应计时，保持编码字节、头部与 Content-Length。AHC 的背压消费不是远端确认：本机 NIO/socket 缓冲仍可能保留尾部。WS 在 frame 的 transport write future 成功后启动，亦不表示提供者已消费。上游请求 frame 不另加早于总期限的固定五秒限制；控制帧和下游慢消费者策略不变。

大于 8 MiB 的上传结束（含失败/取消）记录独立有界 info，只有固定传输、结果、大小桶和上传耗时桶，不记录正文、身份或精确长度/时间。无额外后台任务或重试。

## 验收

真实 macOS binary + loopback 合成提供者：HTTP/WS 慢读超过首响应期限后成功、快读静默在上传后首响应期限失败、永不读完在总期限失败、上传中取消；核对编码字节、头部、单次发送、账本和账号健康。定向检查后，最终仅运行一次完整 backend verify，不并发构建。

## 迁移与回退

无 schema 或配置迁移。回退恢复旧计时起点，慢上传可能再次过早失败。无真实订阅、部署或 Linux 验证；传输缓冲边界不是提供者收完的精确时刻。
