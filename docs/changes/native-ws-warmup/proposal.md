# 原生 WebSocket 预热的空输出

P14／P15 允许无生成内容的预热生命周期。Rust 将显式 JSON `output: null` 与非空输出数组及畸形类型一同拒绝，Swift 对照允许该空输出形状。Rust 预热应接受省略、null 或空数组三种空输出表示，并保留收到的响应封套。非空输出数组、其他 output 类型及不属于既有例外的非生命周期事件继续拒绝。

在现有私有协议拒绝日志中使用固定原因区分 lifecycle output 与非生命周期事件。名称已知但形状未纳入预热的辅助帧保留现有拒绝，可用固定原因继续核对实际组合。取样沿用现有限速，原因字段由网关常量生成。用量、终态、响应归属、1009 和重放规则沿用原契约。

自然预热失败的观察窗口出现 `warmup_websocket_timing` 分类。固定分类可指出拒绝分支，无法重建实际帧形状。Swift 对照会在预热中透传无输出的 `responsesapi.websocket_timing`。Rust 只对证据覆盖的封套增加放行：事件名、JSON 数值 `duration_ms`，以及可选的有效 `stream_id`。额外成员、非数值耗时以及附带响应或业务内容的封套继续沿用原隔离与拒绝规则。其他观察到的 timing 封套须先核对契约。

该例外仅在原生 WS 预热校验中生效。沿用已有路由及事件大小、归属、进度、用量和终态规则，耗时帧仍作为可能已处理的证据，禁止使用未处理的 1009 例外。部署与回退沿用现有二进制替换流程，无 schema、配置或持久化格式迁移。回退本次变更会恢复耗时帧的预热拒绝。
