# 管理工作区与组件基础

依据 P11/P12、管理会话与用量契约，保留 React/Vite 静态 SPA 和 feature 组织，引入 Mantine/表单、React Router、Zod，并在只读用量查询试用 TanStack Query。以密钥管理→创建/编辑→独立用量为完整闭环；账号沿用业务控制逻辑，接入统一登录和会话失效边界。

采用 hash 路由，避免扩大 Swift 静态资源路由；筛选入 URL，秘密、CSRF、授权回调不得入 URL 或持久缓存。统一 session owner，401/会话更换/登出立即结束旧 owner、卸载私有视图并取消查询；登出结果未明时仅允许重试登出。一次性秘密仍只保存在短寿命局部状态，不放 Query mutation cache。变更失败不自动重发，未知结果必须成功重读后解锁；离开页面不能绕过该屏障。

密钥列表主导布局；创建和编辑使用抽屉，轮换和一次性秘密使用弹窗；高级限额按需展开。用量一级导航，URL 保存已应用筛选；游标仍是同一查询快照的局部状态。保留部分/缺失证据、全时间未知暴露、UTC区间与大整数精度。现有请求封装继续承担同源/no-store/CSRF/期限。

验收：定向组件失败/竞态测试、完整前端类型/构建/测试/浏览器场景，实际合成后端与大屏UI操作，Linux静态构建/服务边界。集中提交后review，主Agent修复相关回归；没有Swift业务变更不重复后端全集。Desktop/真实订阅/M5/O14缺口保留。

实测发现原管理入口异步writer写入后立即关闭，较大JS资源可在463779字节声明下仅收到327212字节。此闭环包含必要的管理响应发送完成修复：在既有1 MiB响应/5秒写期限内等待NIO最终flush promise，再允许owner关闭；不放宽CSP、连接容量或正文/响应上限。增加真实socket并发/慢读/中断回归，两平台集中验证受影响路径。
