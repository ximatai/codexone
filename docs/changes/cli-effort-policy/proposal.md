# Responses 推理档位授权

明确档位限制对完整历史和增量续接的约束，并定义每轮准入的校验和账本语义。

## 问题与目标

固定基线 `c3f4d7a9001ca783c9a0c36f76c5c0c9624e84a3` 的 Rust 网关按请求顶层推理档位校验 Key、记录准入。已有本机观察表明，官方 CLI 0.171.0 可在顶层基准保持稳定时提交档位变化，并在后续轮复用上下文。当前网关可能派发超出 Key 档位授权的请求。合成上游只能确认派发和结算。

[I05](../../reference/specs/identity.md) 要求每个新 turn 和恢复读取遵守当前授权。[P10](../../reference/specs/protocol.md#p10重试超时与外部错误) 约束拒绝和诊断边界。[U10](../../reference/specs/usage.md#u10-补充请求参数观察) 定义请求档位的账本语义。目标是在持久准入和上游交互前落实档位策略，保留获准请求的线协议和既有结算责任。

## 历史和当轮更新

CLI 把经本地 harness 标记的档位变化加入会话历史，请求顶层档位可在上下文窗口内固定。历史里已建立的相同档位可以省略重复更新，成功压缩后可以重新建立顶层基准。完整发送携带仍有效的历史。增量发送仅携带引用响应以后的增量。只有可信续接归属与前序上下文同时可证时，网关才能解释省略的部分。客户端历史的本地标记和网关可验证的授权证据各有自己的信任边界。 [官方 CLI 会话档位源码](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/core/src/session/reasoning_effort.rs#L28-L144) · [官方 CLI WebSocket 序列化](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/core/src/client.rs#L2419-L2448)

按最后一次更新记录当前选择的做法可参考 codex-lb。对于授权，网关需要验证当前可见历史和经可信证据继承的各个档位片段。单个末值只适合作为完整且可解释上下文的本轮投影。 [codex-lb #2665](https://github.com/Soju06/codex-lb/pull/2665)

## 最小实现建议

- 每个新生成 turn 读取当前 Key、模型及适用策略，计算显式档位限制的交集。已启用的限制下，顶层档位仍须显式有效且获准。对完整、可解释的上下文，按输入顺序校验每个影响档位的值。全部获准后才派发，保留原始顺序和字段。
- 历史超出授权、档位语义不明或所需前序上下文无法证实时默认拒绝。相邻合法更新逐项校验。档位更新项中可能影响解释的未知字段、非法值和不支持的形状返回明确错误。与档位无关的扩展继续遵守现有透明转发契约。
- 首版只在事实完整的活动原生 WS 上继承已验证的上下文。沿用可信响应绑定核对 Key 主体、模型和上游来源。由活动续接链的 owner 保存有限的档位事实和完整性标记，随连接和上下文回收。每轮重新检查这些事实和当前策略。历史曾获准只说明当时的结果。前轮使用的档位在当前策略中失效时，即使本轮选择获准，也拒绝继承该历史。
- 持久准入复核 Key revision、模型及档位授权。预校验和准入之间发生策略变化时按最新策略重新校验或拒绝。确定拒绝时沿用有界诊断，确保零上游派发、零新持久 intent。已派发的旧轮沿既有生命周期结算。
- HTTP 全历史按完整可见输入校验。HTTP、换连接或重启后的引用续接如果缺少足以还原档位授权的证据，明确拒绝。客户端可从独立上下文开始，或按现有协议提供完整历史。预热、压缩及其他能建立引用上下文的路径也须提供可验证的档位事实。现存响应绑定只证明归属，未知执行结果不足以证明档位。
- Key、模型、实例均无档位限制时，沿用既有透明转发。显式允许目录内全部档位时，包含已知有序更新的完整输入应继续通过。超出目录的值和不明续接依然受显式策略约束。

## 账本语义

| 事实 | 定义 | 来源 |
| --- | --- | --- |
| 请求值 | 客户端顶层档位的观测值，保留已定义的缺失和非法值语义 | 现有 `admission.reasoningEffort` |
| 有效授权值 | 在完整且可解释的上下文中，按当前策略校验后的本轮档位。整段历史仍须逐项满足授权 | 纯策略函数的结果。首版可仅用于准入，如需持久化则另定兼容字段，旧行留空 |
| 上游确认值 | 可信上游通过明确契约给出的本轮实际档位 | 目前缺少经验证的来源。待独立验证后再评估字段 |

拒绝记录沿 P10/U10 仅投影可验证的模型、有限档位标签和固定原因。结算使用可信用量证据。网关接收、转发或结算请求均不足以确认提供者实际档位。

## 纯策略函数预期值

设顶层基准为 L，H 和 M 为另外两个已知受支持档位。函数输入包括当前策略交集、显式顶层值、有序档位事实和前序上下文完整性。续接示例中的历史均指已通过来源核对的事实。

| 场景 | 当前允许 | 档位事实 | 期望 |
| --- | --- | --- | --- |
| 新轮 | L | L，无更新 | 允许，授权值 L |
| 缺少显式基准 | L | 顶层缺失，当前选择 L | 拒绝，缺少必需字段 |
| 有序更新全部获准 | L、H、M | L，按序进入 H、M | 允许，授权值 M |
| 历史包含超出当前授权的片段 | L、M | L，历史含 H，本轮选择 M | 拒绝，历史档位不获准 |
| 相邻合法更新 | L、M | L，相邻合法更新分别选择 M、L | 允许，授权值 L |
| 更新项语义不明 | L | L，更新项含影响档位的未知字段或非法值 | 拒绝，无法可靠解释 |
| 引用续接且本轮无更新 | L、H | L，前序最终处于 H | 允许，授权值 H |
| 前一轮高档后降权 | L | L，前序处于 H，本轮无更新 | 拒绝，当前授权已收紧 |
| HTTP 全历史重放 | L、M | L，完整历史含 H，最后选择 M | 拒绝，历史档位不获准 |
| 重启后引用续接 | L、H | L，前序档位未知 | 拒绝，无法核对 |
| 显式允许整个受审核目录 | L、H、M | L，输入完整且所有值均已知 | 允许，按顺序得出本轮值 |
| 无任何档位限制 | 无限制 | 既有协议可转发的扩展或历史 | 透明放行；语义不明时授权观测留空 |

## 恢复与回退

首版无需 schema 迁移。活动连接的档位事实随服务退出失效，旧绑定和旧账本继续供既有功能使用。跨重启保留档位事实需要独立评审原子写入、绑定范围、记录大小、过期和旧数据语义。回退会恢复旧授权边界，部署回退需要说明这一差异。拟议授权收紧沿用现有用量结算和未知执行责任。
