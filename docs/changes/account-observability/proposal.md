# M3 账号可用性与用量解释

## 业务闭环与依据

依据 I05/I08/I18、U03/U06/U10/U11/U12、A08/A09，使管理员可以从同一控制台解释账号暂不可用、订阅窗口/重置及每个 Key 的本地消耗。主 Agent 完成后端与可操作界面，阶段内定向验证，闭环后集中提交/review/修复，出口一次完整后端/前端/跨平台检查。Desktop、恢复和真实订阅仍各自保留验收。

## 取舍

- 额度通过可信提供者的只读 usage 接口观察。主/次窗口保持上游角色及实际时长，不假设永远对应五小时/一周；保留已用比例、重置和观测时间。附加限额按提供者标识展示，不猜测其与本地模型的映射。
- 新鲜、陈旧、不可用明确区分；失败保留最后成功值及失败时间，不归零。订阅额度与 Key 的请求/并发/未知暴露/估算费用并列解释。额度观测不直接作为所有模型的硬禁用条件：附加额度、credits 与计划含义不能从一个窗口推断。
- 提供者明确认证拒绝、429 与 5xx 分别记录。当前版本的认证拒绝阻止新派发，凭证刷新/重新授权产生新版本后才恢复；429/5xx 使用有界模型冷却。客户端断开、本地限额/过载、总期限及无法定位原因的失败不扣账号健康。无归属的新请求可选择其他健康账号；持久 intent 后绝不换账号或自动重放，固定连接也不能迁移。
- 只保存固定枚举和时间，不保存上游错误正文、响应头原值、正文/图片或个人账户字段。健康提示与订阅额度是观察，未知执行仍独立保留，不因冷却结束或额度重置退款。

## 数据与所有权

SQLite v5 增加准入时间、服务端请求标识、受控执行结果/失败分类及账号观测/健康数据。v1—v4 须显式离线备份迁移；旧记录无精确准入时间则标 unavailable，不从 UTC 日窗口伪造小时。旧二进制拒绝 v5。用量结算与健康结果在既有最终化责任下写入；额度 GET 无旋转令牌副作用，但提交仍核对身份和凭证版本，旧结果不能覆盖新授权。

额度观察由 Runtime owner 监督，最多 64 个账号工作、4 个网络工作、64 个管理等待者，单账号只有一个工作；定时与手动请求共用容量。管理等待者取消不取消已有 owner，关闭停止接纳并等待工作；额度 GET 使用独立四名额 HTTP owner，不占凭证授权/刷新网络容量；额度读取失败不扣执行健康。网络总期限、响应大小和固定可信目标受限，不跟随重定向或调用付费生成。周期只处理允许使用/排空的账号；禁用账号保留历史，手动读取有效凭证可查看额度，过期禁用账号须先显式刷新凭证。enabled/draining 的过期访问凭证可加入已有共享刷新，不建立第二套刷新 owner。

账号健康冷却按当前配置的最多 32 个模型保存；配置装配时清除不再支持的模型作用域，当前认证版本屏障独立保留。托管的新准入必须携明确模型，历史缺失模型仍只读保留为 unavailable。Core 准入事务复核健康/冷却与既有账号、Key、归属和资源条件；不能仅在传输快照中过滤。readiness 同时核对本地可解密账号与其可用模型交集。

统计按 Key、UTC 时间范围、模式和失败类别进行有界查询/聚合；至多 31 天、744 个小时点，明细分页至多 100 条。总量同时给出完整、部分、不可用及在途/unknown 数量；缺失用量不填成实际零。迟到证据按最新账本反映，Key 轮换保持原标识，generation/warmup/compact 可区分。历史无时间记录单列不可定位数量；现有全局账本容量仍为上限，不引入无限内容历史。查询由主库 owner 派生的单个只读 WAL reader 承担，只有一个在途统计、查询总预算和取消路径；不把统计扫描排进核心事务队列。超过 JavaScript 精确整数范围的累计指标用十进制字符串传输；部分证据的数值显示为已观测下界，不能将未知分量展示为实际零。已识别 Key 的合法请求在准入前被拒绝，只记有界、可清理的脱敏诊断，不创建执行 intent 或消耗核心审计预留；执行账本与诊断保留策略分别解释。

## 产品入口与验收

账号界面展示认证/冷却原因、主次窗口、重置/观察/失败时间，支持有明确结果的手动观察；读取失败暂停依赖旧状态的变更。用量界面提供时间/Key/模式/错误筛选、趋势和有界明细，解释 UTC、估算及未知项。沿用管理 session/CSRF/登出边界；大屏优先，实际浏览器操作验收。

验收覆盖可信目标/身份与重定向隔离、非付费 GET、空/部分/畸形/过大/超时/认证失败、陈旧数据保留、刷新/重新授权竞争、工作容量与关闭；真实 HTTP/WS 新请求健康分流、固定连接不可迁移、本地失败不扣健康；SQLite 升级/回滚/拒绝旧库、时间边界/跨 Key/轮换/迟到更新/未知完整度/错误筛选。前端阶段成果集中 subagent review，主 Agent 修复，再做界面和阶段出口验证。
