# 管理模型目录与 Key 推理强度

Key 表单从网关启动配置取得候选模型。管理员需要改私有配置并重启才能更新目录。将目录管理移到管理台，并允许对每个 Key 的每个对话模型设置可用的推理档位。

## 模型目录

- 账号池管理员可手动刷新所选账号的模型候选。显示来源、观测时间、模型 ID 和可识别的推理档位。发现请求沿用受信任的账号访问入口，限制超时和响应大小。启用时核对确认弹窗所展示的候选版本。刷新失败保留上次结果并显示其时间；候选缓存可重建，启用状态须持久化。
- 管理员审核并启用模型。对话模型启用前核对实际路由、完整 Codex profile 和必要的能力及费率配置。图片沿用独立的模型映射和授权，只有验证过的来源才用于发现图片候选。发现的模型绑定至提供该候选的账号。资料不完整的候选可查看缺项，需完整资料后才能启用。
- 管理 API、Key 表单、客户端目录和执行准入使用同一份生效目录。目录修改使用 revision，写入失败沿用上一个生效版本。保存时提示选择「全部模型」的 Key 会获得新增模型。显式 Key 保留已选 ID，退役项标记为不可用；退役阻止新请求，已准入请求按原规则收尾。
- 现有启动配置和审核过的 profile 提供初始目录。目录更新以完整版本生效，重启后保留管理员已提交的版本。并发更新时同时校验目录版本与 Key revision，避免使用已失效的模型或档位保存新授权。

## Key 推理强度

- 每个可用的对话模型独立选择「跟随模型支持的档位」或「指定档位」。指定档位使用显式集合，例如模型 A 允许 `low` 和 `medium`，模型 B 允许 `high`。档位来源为已审核的模型 profile，具体可选值以该模型为准。旧 Key 缺省沿用当前行为；图片生成与参考图编辑继续由图片能力及图片模型范围授权。
- 限制按模型执行。显式请求的档位超出 Key 策略时，在接触上游前返回可诊断的拒绝。当前无法从目录证明上游执行时实际采用的缺省值，受限请求须显式指定允许的档位。用于用量展示的清洗值不得作为授权依据。原始字段缺失、显式 `null`、类型非法以及合法档位须在授权前可区分。
- Codex 目录对受限 Key 只呈现可用档位，公布的默认档位须在允许集合内。若需要客户端显式发送档位，须验证客户端确实发送；不得把目录中显示的默认值当成已经验证的上游缺省行为。目录和实际授权都按新 turn 生效，显式档位退役后自动从有效范围移除。
- 所有实际转发推理档位的受管 Key 请求共用授权逻辑，覆盖 Responses HTTP/SSE、原生 WS 新 turn 和支持该字段的 compact 路径。在 SQLite 持久准入核对 Key revision 和同一策略。连接预热与其他不执行该档位的内部操作按现有契约验证。

## 数据、兼容与验收

保留存量 Key 的模型范围和旧管理 API 调用的既有授权。旧客户端更新 Key 时，省略新增策略字段须保留该策略。旧二进制可能忽略新增限制，持久化之前必须建立版本屏障，使不认识策略的版本拒绝打开已启用该能力的库。回退按升级前备份和执行责任核对流程进行。

首次交付范围为手动刷新、显式启用和按模型勾选推理档位。持续同步、自动启停、自动改写请求档位和模糊匹配不在本次范围。规范涉及 [I03 及受管 Key](../../reference/specs/identity.md)、[A02 与 Key 管理](../../reference/specs/control-plane.md)、[P16 模型目录](../../reference/specs/protocol.md#p16受控模型目录)和[模型 profile](../../reference/model-profiles.md)。

用合成目录验证发现、启用、失败保留和重启。用真实 HTTP/WS 入口验证旧 Key、合法档位、越权档位、遗漏档位与并发修改，并核对拒绝未触发上游请求。单账号验收验证候选来源、Codex 客户端对目录的实际采用和档位发送；多账号差异用合成账号验证。
