# 试运行加固：未结执行容量与核对、凭证到期与账号名展示

日期：2026-10-31。修改[用量](../../specs/usage.md) U07 的全局/身份未结容量与人工核对，[管理面](../../specs/control-plane.md) 账号元数据与提醒规则。

## 问题

1. 核心库全局与身份（账号）范围的未结执行（`state != settled`）上限硬编码为 32，跨窗口不释放，也没有可用的人工核对入口。客户端取消、超时、断线都会留下 unknown。按旧服务近 7 天约 57 次断开和 48 次中断估算，正常使用几天内就会累计到 32，之后所有请求被准入拒绝，相当于整站停服。试运行库切换一小时后已有 8 条。
2. 首页“需要处理”只要存在任一 unknown 就一直提示，正常取消也会触发，真实风险被淹没。
3. 账号接口把 `accessExpiresAtUnixSeconds` 固定返回 null，管理员看不到访问凭证何时到期，无法安排首次主动刷新的观察。
4. 订阅账号未命名时，首页额度卡、用量明细与活动列表直接显示 UUID。

## 行为

### 未结容量

- 全局与身份范围的未结数量上限由 32 调整为 1024（命名常量）；主体保留原持久限额，Key 按原 Key 策略（null 不限）。未结预留金额上限不变。
- 仍为断路器：达到上限拒绝新准入，不自动释放、不按时间过期。

### 人工核对（U07 的人工释放）

- `POST /api/executions/unknown/release`（管理员，复用 A10/A11 认证、来源、no-store、容量契约）。请求体 `{ "beforeUnixSeconds": int, "expectedCount": int }`，两字段必填，未知字段拒绝。
- 在单个写事务内：选出 `state='unknown' AND created_at_epoch < beforeUnixSeconds` 的执行；数量与 `expectedCount` 不一致返回 409（CAS，防止误释放新出现的项）；一致时全部转为 settled，保留原 outcome/failure，用量查询完整度保持 unavailable（已有可信部分数值仅保留下界，不得记零、不补估算）；迟到部分证据不恢复容量占用，迟到完整证据允许修订统计；写入一条治理审计（动作 `release_unknown`、数量、截止时间、执行时间，不含请求标识列表以外的正文）。`intent`（在途）不受影响。
- 返回 `{ "released": n }`。0 条时 expectedCount=0 也返回成功。
- 用量统计中这些执行仍显示为用量不可用；“unknown/待核对”计数相应减少。

### 提醒

- `unresolved_executions` 改为按容量比例：未结数 ≥ 上限 50% 为 warning，≥ 80% 为 critical；低于 50% 不提示。detail 增加 `limit` 与 `unresolvedCount`（含 intent/unknown 及恢复缺失暴露）；`count` 保持可释放 unknown 数。
- 首页该提醒项提供“核对并释放”操作：确认对话框说明含义（这些请求的真实用量无法得知，释放只解除容量占用，统计中仍显示用量未知），确认后以当前时间与当前 unknown 数调用接口；409 时提示数量已变化并刷新。

### 凭证到期

- 账号读取返回真实 `accessExpiresAtUnixSeconds`（Unix 秒，非秘密）；不改 schema，不在应用层外暴露凭证。取值失败或未知为 null。
- 订阅账号页与首页额度卡显示“访问凭证约 X 后到期”；15 分钟提前刷新沿用现有授权/额度失败规则体现（不新增 kind）；临近到期本身不冒充失败证据。

### 账号名

- 管理台统一用账号显示名；未命名时显示“未命名账号 · <ID 前 8 位>”，并在订阅账号页提示可设置名称。用量明细、活动列表、提醒中只有账号 ID 的地方按账号列表映射显示名，映射不到时同上回退。

## 不做

- 自动核对或按 TTL 释放 unknown；按条选择释放；可配置阈值。

## 验收

- 存储：上限常量；释放事务的 CAS 成功/409、只影响截止前 unknown、intent 不变、审计写入、完整度不变；释放后准入恢复（全局/身份上限边界测试）。
- 管理 API：鉴权、来源、未知字段/缺字段/负数拒绝、繁忙、no-store。
- 提醒：50%/80% 边界与低于 50% 不提示。
- 账号 API 返回真实到期时间；失败为 null。
- 前端：释放流程（确认、成功、409）、到期展示、账号名回退与映射；1440×900 走查。
- 规范同步；`verify.sh --backend`、`verify.sh --web --chrome`；主 Agent Linux verification。
