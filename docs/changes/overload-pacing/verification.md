# 过载节流评审与验证

记录 PR 与 main 集成后的功能、所有权边界及实际验证。

## 评审调整

- 合并已发布到 main 的每日 Token 治理、管理界面和 CI 脚本，保留双方变更日志；没有改写共享历史。
- 原协调器在过载等待期间保留全局最多16个finalizer票据。现仅在确认未建intent的过载结果后归还票据，等待结束后重新预留，再重新准备候选与原子准入。已建intent的路径仍先获得结算能力，操作阶段不会被重试。
- 原选择逻辑在检查账号并发前就记录冷却等待时间。现只有仍有并发容量的候选可参与等待和Retry-After选择，满并发账号不会让请求无效等待，也不会掩盖其他候选更长的截止。
- 同步已合并Token契约和完整回退限制；移除提案中具体运营流量数字，仅保留问题机制与合成验收。

## 本地验证

2026-11-02，macOS arm64、Apple Swift 6.4，使用合成账号与本地提供者：

- 定向过载/等待者测试18项通过，包括真实HTTP/WS等待时票据为零、其他健康账号仍可转发、取消后无新增intent或健康故障。
- 新增满并发候选不参与等待，以及可用候选的20秒Retry-After不被满并发候选2秒截止掩盖的SQLite测试；等待期间达到每日Token上限后拒绝创建intent。
- 完整Swift测试390项、34个后端验收脚本全部通过；追加原生WebSocket回归后，定向18项复测通过。
- 原生WebSocket长等待返回503及headers.retry-after=20，不新增intent、不改换固定账号；保留原准入拒绝时的连接结束策略。
- 文档、架构、Swift格式与差异空白检查通过。

未连接真实订阅或部署实例，未在本地构建Linux镜像。此阶段不代表Linux完整CI或真实客户端兼容验收。
