# M1 持久执行内核

## 目标与边界

按里程碑 M1，实现 E01—E05、U02—U07、O01/O02/O09、I04 的合成执行切片。Core 定义业务命令与执行协调；SQLite 适配器原子处理准入、归属与幂等用量；Runtime 监督有界 finalizer。实例锁、WAL/FULL、外键和有限 busy timeout 启动校验，恢复后方可准入。

不接真实身份/凭证、OAuth 或协议转发，不创建业务管理页面或正文缓存。健康入口仍不能代理生成。只建立空库到 v1 的事务迁移；未知或需升级的既有 schema 拒绝启动，未来非空库迁移须先一致性备份再显式执行，不自动破坏性升级。

## 设计与验收

准入先预分配 finalizer ticket，事务持久身份、策略/窗口版本、预留及 dispatch intent 后才能调用合成上游；任何可能发送的失败保守保留未知暴露。绑定屏障先提交再交出对象 ID。结算证据采用有版本的累计快照，去重并保留迟到用量；完整、部分、不可用分开，估算费用不等于订阅余额或硬上界。

每主体、上游身份与全局分别校验请求/活动/未知数量与估算预留；未知暴露跨重启继续占用，禁止自动退款/重发。DB 工作在专用串行队列执行，提交前取得有限容量；结算保留独立容量，不与准入争用。字符串/命令、绑定与证据数量有硬限。

真实临时库测试竞争、重复/冲突结算、超预留、迟到证据、归属冲突、库不可写、实例锁和 schema 失败；真实子进程在 intent/绑定/结算前后 kill 重启核实保守恢复。kill 不代表掉电测试。主 Agent 自我复盘并提交，再由 subagent review，主 Agent 修复复验。
