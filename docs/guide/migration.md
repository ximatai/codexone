# 从 codex-lb 迁移

将自己使用的账号与设备接入迁至独立 CodexOne 实例，保留清晰的权限和回退边界。

## 前提

使用独立数据库、卷、管理员秘密和主密钥，先完成[新安装](linux-installation.md)。不得让两个服务共写库或无协调地刷新同一个旋转 refresh token。

## 兼容范围

| 使用路径 | 迁移要求 |
|---|---|
| Responses HTTP/SSE、原生 WS、HTTP→WS 桥接 | 保留 `/backend-api/codex` 前缀，亦支持 `/v1`；按客户端版本分别核对 |
| 模型目录、工具、预热、压缩与续接 | 配置受信模型能力；旧会话私有 ID/密文上下文不保证可迁移，先用新会话 |
| 图片生成、参考图编辑 | 单独配置图片模型与 Key 权限，参数组合由提供者判定 |
| 辅助控制接口 | 仅[显式允许路由](../reference/control-endpoints.md)；遥测本地返回 202 |
| 账号登录与额度 | 在新侧重新授权自己的账号；不复制登录缓存或凭证库 |
| Key | 推荐换发；有条件离线导入已核验 SHA-256 摘要，默认禁用 |
| 用量与恢复 | 两侧账本独立；不迁移余额、执行历史或旧输出，不承诺断线无损恢复 |

此表归纳行为兼容边界，不能证明任意 codex-lb 版本、客户端或提供者组合可用。实现自行编写，来源见[来源声明](../reference/provenance.md)。

## 操作顺序

1. 记录源侧模型、Key 权限和限额语义，准备可恢复的私有备份与回退配置。
2. 在新侧重新授权账号；协调源侧停用，避免同凭证并发刷新。核对模型、价格、TLS 和健康状态。
3. 换发各设备/工具 Key；确需保留原字符串时按[摘要导入](key-import.md)转换，仅受支持策略可导入。带过期、停用或不可等价限制的条目隔离，不删约束放宽权限。
4. 先用合成上游与新会话检查目录、工具、传输与失败处理，再在自己确认条款和额度的前提下核对实际客户端。
5. 修改客户端地址或自己的反代路由。核对归属与用量，保留源侧回退材料，避免两个服务同时处理同一逻辑请求。

回退需核对新侧新增执行/未知责任和凭证轮换。切换入口不撤销已执行请求，源侧余额不能覆盖新侧用量。具体转换与切回流程见[迁移核对](migration-cutback.md)。
