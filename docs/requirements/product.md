# 产品目标与范围

定义个人自托管的使用目标与能力边界，当前交付范围见[项目状态](../../STATUS.md)。

## 服务对象与价值

个人自托管 Codex/Responses 协议网关。管理自己的 ChatGPT/Codex 订阅账号，为自己的多台设备和工具分别发放 Key，提供权限隔离、用量治理和可靠转发。

## 首版目标

- 单管理员域、多上游账号、多 principal/Key；订阅账号池优先。
- 以 Codex Desktop 为主要兼容对象，CLI 补充验证；文本、客户端函数工具、连接预热、压缩续接及 HTTP/WS 使用路径。
- 原生 Images generation 与有边界的 edits（参考图编辑），以及 Responses 图片工具；无需将其扩展为通用文件服务。
- 对话模型与图片生成权限分开，关闭生成不误伤视觉输入。
- 可用性优先，保护订阅账号；显式 Key 限额、账号并发和存储安全可阻断，用量/费用参考阈值只提醒，缺失标未知并披露可能超额。
- 安全初始化/授权、账号/Key 管理、请求诊断、按 Key 用量/趋势；分别展示订阅剩余额度/重置时间与本地用量/估算费用。
- 升级、备份恢复、旧服务替代与回退闭环；支持弱服务器运行，CI 承担构建。

## 后续恢复目标

有限正文/图片恢复缓存尚未交付，后续须先验证实际客户端读取契约，再实现限期限量、加密隔离和删除，不自动重新执行模型或工具。它不属于 v0.26.1 的交付能力。

## 聚焦范围

首版不承担支付/严格收费、多管理员 RBAC、公网 SaaS、多节点 HA、永久历史/相册、通用文件服务或未验证的后台/远端工具。公开 API 上游及超出已验证客户端契约的图片扩展以后按需求评估。

## 验收目标

使用者完成文本/工具/出图/参考图编辑闭环；管理员能解释权限、调度、用量与恢复结果。主体与账号不串用，本地资源有界，失败不导致静默重复执行或用量丢失。缓存必须对应实际可用且明确说明的客户端恢复方式；具体接口未验证前不承诺兼容。详见 [规范](../reference/specs/README.md)。

## 现有服务替代基线

首版须覆盖已确认的 CodexLB 使用效果：Desktop 自己的多设备 Key 接入订阅账号、模型选择及图片独立权限、HTTP/WS 与 HTTP→WS 桥接兼容、预热/压缩/续接、图片生成及参考图编辑、账号额度与按 Key 用量/错误诊断。模型名称与客户端版本采用验收时明确的清单，不写死为单一模型或声称兼容所有版本。

替代验收包含现有 `/backend-api/codex` 接入前缀、域名反代配置、账号与 Key 迁移，以及切回旧服务；内部实现和管理页面布局无需照搬。安全重试与恢复差异必须逐项披露，不能靠可能重复执行的重放伪装等效。规范条款及验证要求分别见 [protocol](../reference/specs/protocol.md)、[operations](../reference/specs/operations.md) 和 [verification](../development/verification.md)。首版满足这些目标须由实现证据证明，文档同步不代表已可替换生产服务。
