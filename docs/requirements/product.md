# 产品方向与范围草案

本文件是可演进工作假设，不是永久业务边界。遇到协议限制、实现困难或更优方案时，按 [治理](../governance.md) 提出影响、证据与推荐，及时与用户沟通；进度与交付证据只见 STATUS。

## 服务对象与价值

面向自行管理订阅上游和下游 Key 的自托管使用者。以稳定协议接入、身份隔离、用量解释与故障恢复形成产品价值，而非纯 HTTP 转发。技术方向见 ADR，不在产品文件重复依赖版本。

## 首版工作范围

单管理员管理域、多上游账号、多 principal/Key；订阅账号池优先。目标覆盖文本、客户端函数工具、经验证的压缩续接与原生图片生成。管理闭环包含初始化/授权、策略、诊断/核对、升级备份及回退。

对话模型与图片生成权限分开，视觉输入单独判定。请求/并发硬限、token/图片治理、金额估算，兼容优先且披露可能超额。正文恢复缓存限期限量并加密；恢复语义先按 [候选契约](../specs/recovery-contract.md) 验证，不能把保存内容等同于原生 Codex 自动续播。

## 暂不纳入的方向

支付/严格计费、多管理员 RBAC、公网 SaaS、多节点 HA、永久历史/图片相册、通用文件服务、图片 edits、未经验证的后台/远端工具，暂不作为首版工作范围。公开 API 上游可后续独立适配。以上均是聚焦手段，可凭需求与证据调整，不是禁止讨论的业务禁区。

## 验收取向

使用者完成安全接入、文本/工具/出图闭环；管理员能解释调度、权限、用量和恢复失败。隔离、取消回收、未知执行、恢复安全及弱服务器资源证据见 [规范](../specs/README.md)。承诺范围必须与实际受支持客户端/版本吻合。
