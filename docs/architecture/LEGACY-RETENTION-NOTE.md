## 两种不同的记录

常规 `RequestLog`（`app/db/models.py:441`）以身份、模型、用量、耗时、状态和诊断元数据为主，不是完整对话库。粘性会话记录主要维护会话与账号归属。

HTTP 会话桥接另有持久恢复记录：`HttpBridgeOperationRecord`（同文件约 1974 行）包含 `request_text`，`HttpBridgeOperationEvent`（约 2019 行）包含 `event_text`。提交路径把请求内容交给操作账本，响应路径保存可重放的 SSE 事件。因此部分桥接请求会保存正文；如果其中包含内联图片数据，也可能涉及图片内容。这不代表每种 HTTP/WS 路径、每次请求都被保存，也不构成独立图片相册。

## 源码默认值及其范围

`app/core/config/settings.py` 中 HTTP session bridge 和 operation ledger 默认启用；恢复 spool 默认保留 7 天，清理由调度器执行。每个 operation 的响应事件 spool 默认上限为 2 MiB；**这个上限不等于请求正文、整条会话或数据库总大小上限**。达到事件上限可能导致缓存不完整，不能继续承诺可重放。

`durable_bridge_repository.py` 保存请求与事件并从完整的记录构建有界恢复 transcript。所检查的这些写入路径未显示对正文进行应用层加密；这不能证明线上磁盘、卷或备份是否加密。

默认 ambiguous continuation recovery 仍为 `fail_closed`。即使保存部分内容，也不能保证任意断线无损恢复或安全重放已经执行的生成。

## 对 CodexOne 的启示

默认不持久保存正文/图片是一项明确的产品选择，与旧服务的短期恢复缓存有差别。选择它意味着保留归属、用量及脱敏诊断，但本地映射不足以重建上游上下文；必要时客户端需要主动重建请求。运行中的有界内存缓冲仍不可避免，禁止落库、正文日志、临时正文文件并控制崩溃转储，才是可验证的持久留存边界。

将来若增加短期恢复缓存，应单独设计显式开关、加密、请求与响应各自及总量限制、保留期、删除、备份清理和重放安全；不把它暗中混入普通诊断。

## 后续产品决定

用户于 2026-10-21 在了解以上差异后选择：CodexOne 首发保留有上限、有期限的正文恢复缓存。前述“不持久保存”段落保留为取舍背景，最终实施以 [架构 §9.1](ARCHITECTURE.md#91-短期正文恢复缓存用户已确认首发) 为准。
