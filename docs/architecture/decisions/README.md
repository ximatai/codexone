# 共识决策

记录已采用的工作共识及理由，不代表方案不可调整。遇到困难或更好证据，按治理流程沟通；进度只见根 STATUS。

[稳定接入与有限恢复的取舍](compatibility-policy.md)：结合CodexLB源码与Issue/PR讨论选定的期限、模型profile、恢复、图片与错误治理方向，以及不吸纳项；具体实现和当前限制以规范/STATUS为准。

## 技术栈与组织

Swift 6 严格并发，NIO 掌控数据面，Vapor 承担管理 API，AHC 调用上游；SQLite 单节点。管理台 TypeScript/React/Vite 静态 SPA。Linux amd64 OCI/Compose，由 GitHub CI 构建，服务器不承担编译。

依据：传输实验表明应显式控制 channel 生命周期；单体和 SQLite 适合小规模自托管，静态前端无需 Node 运行服务。代价是维护窄传输层，SQLite 不提供多写 HA，Swift 并发检查不能替代事务与生命周期验证。

### 管理台组件与状态基础

保留React/Vite静态SPA和feature聚合，采用React Router hash路由、Mantine/表单和Zod；只读用量以TanStack Query做有界内存查询试点。理由是重复会话/表单/弹层已增加维护成本，当前无需新增Node运行服务。会话owner和业务不确定性仍显式维护，通用查询不接管秘密返回或自动重试。Mantine主题/CSP适配用静态CSS、禁用运行时样式注入和Zod JIT，不放宽安全头。TypeScript 7超出当前typescript-eslint peer范围，采用Oxlint的明确规则与Prettier，类型检查仍由锁定tsc承担，不强制安装不兼容依赖。代价是引入依赖/静态包体和少量CSP适配；页面按需加载、资产保持现有容量界限，更新时核对实际CSP和私有状态清理。

### 发行的数据卷与回环边界

Linux Compose 使用 host network 保留网关的回环监听，由宿主 TLS 反代接入；不为容器包装扩大监听面。data 默认使用唯一命名的 Engine 本地 volume，显式 nocopy；秘密保留独立只读文件。依据是共享 bind 的最小 flock 探针不能维持实例互斥，而 Linux 本地卷可维持；空卷 copy-up 还会重置目录属主。初始化只为新空卷设置 UID/GID，既有非空卷归属不符或目录读取失败均拒绝；隔离的短命 root init 不挂秘密、不联网，gateway 保持非 root。代价是数据与迁移备份由 volume 管理，不能把删除卷或复制旧快照当作升级/回退；证据见[安装验证](../../reference/specs/operations.md)。

## 可用性优先、保护订阅账号的用量治理

原“兼容优先用量治理”按[治理姿态提案](../../changes/governance-posture/proposal.md)修订。Key 分配给自己的设备和工具，限额防误用；费用和用量只作观察，不对外结算。少量缺失可接受，必须标未知、不记零。服务可用与账目精确冲突时优先可用；稀缺资源是订阅窗口额度和账号使用模式的安全性。

记账不确定性和观测阈值只提醒。阻断限于管理员显式 Key 限额、保护订阅账号的流量整形、存储与数据安全；单个 Key 的未知账目不能让其他 Key 停服。每个持久实体须有生命周期/保留策略；每个上限须写明保护对象、作用范围、窗口、到达后的降级与余量观测。请求数/费用参考值、每账号并发和存储水位的当前值须可读；订阅额度与本地费用不互相换算。

unknown 保留 24 小时核对期，期满审计关闭，用量仍未知。90 天明细转 UTC 日汇总，按续接期限删除绑定并增量回收空间。代价是无法追溯永久明细或保证费用精确封顶，v10 迁移需停服备份及一次全库重写。断线不证明未执行，关闭不伪造退款/用量；迟到可信证据在明细保留期内仍合并。

## 限期限量正文恢复缓存

正文/图片恢复缓存为尚未交付的设计目标：加密、隔离、固定期限、多级容量限制、删除，默认不备份。它不构成永久历史库，不保证任意断线无损恢复，也不授权模型或工具自动重执行。具体客户端契约和参数需验证，未选择私有扩展协议。

## 首版以现有使用效果作为替代基线

以 Desktop 为主要兼容对象，CLI 补充；首版包含有边界的 Images edits、订阅额度观测、按 Key 用量诊断、旧服务迁移与弱服务器验收。理由是生成之外的参考图编辑、多种传输与日常管理已经属于实际需求，单纯完成新安装或 CLI 演示不能证明可替代旧服务。范围和验收以产品目标及协议/用量/运维规范为准；不复制旧服务内部设计或所有功能，也不放宽安全重试原则。

## 最小持久化适配

持久层使用系统 SQLite C API 的窄适配与串行 DB 队列，业务层只见原子命令。理由是当前功能需要少量条件事务、明确的连接初始化与失败语义，无需引入通用逐表 repository 或完整 ORM；代价是适配器自行管理语句和绑定寿命，必须以真实数据库与失败测试约束。Core 仍不依赖 SQL/NIO；CSQLite 仅为系统库桥接。

## Key 轮换与管理连接


Key 轮换保留标识和治理计数，只替换验证材料；理由是轮换不应赠送新请求/预算额度，历史用量与同主体归属也应连续。显式创建另一个 Key 仍是独立治理操作。最小管理 API 使用独立管理员 Bearer、只允许非浏览器本机请求；浏览器使用 session/CSRF，不以页面存储 Bearer 替代。

管理面同样由 NIO 拥有连接/正文读取/关闭，完整请求交给 Vapor 路由；理由是实际慢速正文实验中，单纯路由超时不能证明底层连接与 collect 资源已结束。复用现有连接 owner，不改 Core 用例、不开额外网络 listener，也不为绕过寿命问题引入代理服务。


## 托管账号准入的语义版本

托管账号 dispatch 快照必须在持久准入事务中与当前账号/Key 一并复核；凭证准备不算取得租约。即使物理表未改，v4 仍升级核心库版本，理由是旧二进制会忽略 admission JSON 的新增字段，不能仅靠可选字段保持“兼容”而丢失授权屏障。代价是 v3 也须停服显式备份迁移；历史缺少快照的 admission 保持可读，执行责任不被删除或重新解释。


### 被动额度与统计隔离

v5 显式升级引入执行时间/结果与账号观察/健康；历史缺时间不从日窗口推造小时。额度只作被动 GET，不从单一窗口实现全模型硬禁用，附加额度/credits 含义未被模型配置覆盖。执行明确 401/429/5xx 决定版本屏障/模型冷却，持续用量责任不随健康变化释放。统计用独立只读 WAL connection 和单查询预算，避免图表扫描进入关键 writer 队列；大整数指标以字符串传输，缺证据继续暴露 unknown。代价是增加一个受主库寿命监督的只读连接与 v1—v4 的离线迁移，不能据此宣称长期容量或真实订阅验收。

## 主密钥维护的离线语义屏障

主密钥采用一个 active、有限 decrypt-only 的独立私有 keyring，沿用 v1 AAD/信封；再加密先独立备份，在同一离线实例锁下分页 CAS 与检查点同事务提交，不改凭证版本、授权或刷新 intent。即使表结构不变也升 schema v8，理由是旧 v7 二进制不会识别新检查点，可能绕过中断维护门禁。代价是旧库须显式迁移，旧 v7 完成 bundle 仅通过显式恢复升级；未完成 job 拒绝服务并需原 active 续作。

旧 key 是否可退役取决于所有存量引用与保留备份，不以线上轮换完成推断。工具核对候选 keyring、声明完整的保留清单及 bundle 恢复来源；原始备份的外部恢复审计、未知副本与销毁事实仍由操作者负责，不自动删除 secret。命令和边界见[主密钥维护](../../operations/master-key-maintenance.md)。

## 物理空间与关键收尾隔离

磁盘压力采用独立实际分配的私有储备文件、水位滞回和 writer 队列最后复核；不把剩余逻辑页或可删缓存当结算储备。先暂停报表/普通管理/观察/诊断，再停止新 intent；关键绑定/结算/刷新收尾及收紧权限仍可使用储备。理由是队列预留不能防止 WAL、报表长读或备份吃掉物理空间；代价是固定预留空间及低水位暂时拒绝可选工作。实际写满仍可能失败，已有持久 intent 保留为 unknown 恢复依据，不许因无法补写 pending 而丢责任。

Runtime 只拥有一个顺序采样/checkpoint owner；磁盘操作留在 Adapter writer 队列，认证观测与健康只读缓存。离线复制按页复核源/目标余量，不能通过维护耗尽核心空间。默认水位是预防性边界，正式宿主容量与完整 RSS/FD/task 回稳另行验收，见[存储压力](../../operations/storage-pressure.md)。
