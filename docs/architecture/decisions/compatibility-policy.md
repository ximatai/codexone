# 兼容性与有限恢复的取舍

记录协议扩展、可靠转发与恢复范围的设计理由。

## 开放协议与严格责任

网关只约束认证、权限、硬引用归属、容量、执行控制、账本及可信用量。其余请求字段、工具声明和事件按协议透传，由提供者与客户端判定。过度校验未知元数据可能在上游已执行后将结果改写为失败，因此不把完整提供者 schema 复制到网关；提供者错误脱敏后保留可操作信息。具体约束见 [P27](../../reference/specs/protocol.md)。

## 长任务与模型目录

总期限、首响应和进度空闲分别受限，keepalive 不证明模型有进展；执行使用准入时预算快照。长任务仍占容量，不以延长超时替代背压与取消。模型能力采用管理员审核的离线 profile，不从模型名推断权限或自动授权新模型；来源陈旧明确披露，价格是独立估算。

## 分层恢复

当前没有客户端正文/图片重读缓存。后续恢复须证明逻辑操作关联、当前权限、身份、代际与有效期；相同正文不能证明重试。读取已有输出、新生成和 unknown 分开，不能靠换账号或重跑工具实现表面连续性。持久 CAS 证明本地互斥，不证明远端只执行一次。

## 图片与路由

视觉输入、原生 Images 与 Responses 图片工具分别授权。原生 Images 直达对应提供者端点，不能使用旧宿主映射改变其传输。图像负载、输出和累计历史各自有界；参数由提供者判定不等于无限容量。模糊结果不自动换账号重放。

## 迁移

Key 摘要只在验证方式与策略可安全表达时导入全新目标，默认禁用。旧表、余额、登录文件和会话不直接迁移；两侧撤销和用量不自动同步。无法表达的限制隔离，不删除限制迁就导入。
