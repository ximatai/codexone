# 实施路线草案

路线表达依赖和验收，不记录进度；允许随困难或更好方案调整，及时说明影响。STATUS 是进度唯一入口。

| 阶段 | 交付 | 出口条件 |
|---|---|---|
| M0 文档基础 | 产品、规范、ADR、架构、交接、目录 | 接手者无需旧聊天即可定位下一任务 |
| M1 持久执行骨架 | Swift 包/进程、合成上游、SQLite、准入/归属/最终化 | 少量 target/owner/事务边界；并发预留不穿透；ID 屏障和故障重启；RC-1 本地契约验证计划先明确 |
| M2 协议与身份 | HTTP/SSE/WS、订阅身份授权/刷新、对象绑定 | 单身份到多账号、首 WS 懒绑定、lane 与失败重试边界、跨主体隔离 |
| M3 图片与恢复 | 原生 Images、统一权限、限期限量加密缓存 | 至少一条明确客户端/版本/调用方式的实际可用恢复路径，不能仅 fixture 或 unavailable；图片入口、缓存容量/删除/代际与核心配额 |
| M4 管理闭环 | React 管理台、初始化、账号/Key、诊断/核对 | 管理员完成文本/工具/图片和排错闭环，权限展示与执行一致 |
| M5 可发布首版 | Linux amd64 镜像/Compose、升级/备份/恢复、容量档位 | 无凭证 CI、显式授权 live 验证、长期资源回稳、可追溯发布及回退 |

M1 的内部单身份切片不缩减正式首版多账号/Key/管理闭环。后续能力可以按依赖交错开发，但不得以“以后补正确性”为由绕过持久/归属屏障。不自动切换 Ali，不在本任务替换实验 GitHub 仓库。

重型缓存建设前先验证 [恢复候选契约](../specs/recovery-contract.md)。若目标客户端无可行恢复路径，及时沟通调整范围/调用方式，不把存储建设完成当作恢复交付。
