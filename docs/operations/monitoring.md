# 健康检查与诊断

区分进程存活、生成就绪与需要人工处理的提醒。

## 日常检查

`/health/live` 反映进程存活，`/health/ready` 反映当前是否可接单。没有可用账号或核心存储异常时 ready 可以为 503；不要因它未就绪而无条件重启，先核对管理面板。

概览的需要处理提醒涵盖账号授权、Key 到期、协议扩展、备份和容量。`/api/attention`、`/api/runtime/storage` 与 `/api/usage/headroom` 只向管理员开放。订阅额度为观测值，未知或陈旧应显示状态；不要用本地估算费用反推账号剩余额度。

诊断只记录固定分类、请求 ID、状态与耗时。公开报告应使用合成复现，不粘贴原始日志、请求正文、授权回调或数据库。聚合计数和运行时间也可能属于私人运营数据，排查材料须另行脱敏。

## 告警后的操作

先保存私有一致性备份和解密依赖，确认是否有进行中或未知执行。核心写入失败时不要反复重试生成；存储恢复和旧快照恢复须遵守维护态流程。网络故障不能证明上游未执行，自动切回旧服务不撤销新增用量。
