# 健康检查与诊断

区分进程存活、生成就绪与需要人工处理的提醒。

## 日常检查

`/health/live` 反映进程存活，`/health/ready` 反映当前是否可接单。没有可用账号或核心存储异常时 ready 可以为 503；不要因它未就绪而无条件重启，先核对管理面板。

概览的需要处理提醒涵盖账号授权、Key 到期、协议扩展、备份和容量。`/api/attention`、`/api/runtime/storage` 与 `/api/usage/headroom` 只向管理员开放。订阅额度为观测值，未知或陈旧应显示状态；不要用本地估算费用反推账号剩余额度。

诊断记录固定分类、请求 ID、状态与耗时。排查 Responses 模型和推理档位拒绝时，可按请求 ID 查私有日志中的 `requested_model`、`requested_reasoning_effort` 和适用时的 `legacy_reasoning_effort`。日志字段和限额见 [P10](../reference/specs/protocol.md#p10重试超时与外部错误)。公开报告应使用合成复现，不粘贴原始日志、请求正文、授权回调或数据库。聚合计数和运行时间也可能属于私人运营数据，排查材料须另行脱敏。

## 线上验收

所有线上验收共用同一枚长期专用测试 Key。凭证存放在受限的私有文件中，日常保持停用。按测试所需设置模型权限、每日 Token 上限和并发。每次先确认 Key 已停用，再启用并执行测试。成功、失败或正常中断都要停用，并重新读取状态确认。其他测试正在使用该 Key 时，等待它结束。

自动化通过管理接口更新同一个 Key。需要生图时，仅在测试期间为它开放已启用的指定图片模型，停用时恢复原图片权限并重新读取确认。读取不到凭证、所需模型不可用或无法确认停用时中止并报告。进程被强制终止或管理接口持续不可用时，恢复后先在控制台确认并停用，核对测试前的权限。验收只记录必要结果和请求 ID，凭证和认证头不写入日志。

## 告警后的操作

先保存私有一致性备份和解密依赖，确认是否有进行中或未知执行。核心写入失败时不要反复重试生成；存储恢复和旧快照恢复须遵守维护态流程。网络故障不能证明上游未执行，自动切回旧服务不撤销新增用量。
