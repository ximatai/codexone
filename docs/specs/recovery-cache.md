# 短期正文恢复缓存规范

- C01：首发必须支持限期、限量的正文恢复缓存；只用于经验证的同一执行恢复，不作为永久历史库。请求/响应及内联图片必须认证加密，主库不得留明文正文副本；认证头和访问/刷新令牌不得入缓存。
- C02：必须按 principal/namespace/identity/attempt 隔离并在读取时校验当前授权、主库归属与 core generation。相同正文不得充当重复执行证明；无可靠 operation/客户端重试契约时恢复 unavailable，普通新请求仍按新执行处理。
- C03：必须同时限制固定 TTL、单操作/主体/实例字节、条目、物理磁盘/WAL、在途预留与写入队列；读取不续期。初始建议档位为 24 小时、32/128/512 MiB（操作/主体/实例），正式值必须经过容量验收记录，不能宣传为已验证容量。
- C04：必须只封存已持久提交的连续事件前缀和可信终态；队列入队/网络发送成功不能表示持久完成或客户端收到。网络与持久化间不确定窗口必须保留 delivery_unknown。
- C05：恢复不得再次调用模型/工具、创建新 attempt 或重复扣收上游用量；无可靠接收位置、内容不完整、过期或副作用不明时必须明确拒绝不确定恢复。不得透明跨账号重建历史。
- C06：缓存故障/超限必须降级为 recovery_unavailable，不得宣称可完整恢复；不能绕过主库准入、ID 暴露屏障或结算。后台写入必须有界、可取消/等待且不阻塞网络 event loop。
- C07：过期读取必须立即拒绝；删除/到期/关闭必须设置代际屏障，writer 在同一事务或等价原子条件中检查后提交，禁止迟到写回填。删除正文不得删除账本/未结项/必要归属。
- C08：缓存必须默认排除备份、诊断包及崩溃转储；主库 restore 必须新 core generation、停止旧 writer 并清空旧缓存。SQLite 清理须覆盖 WAL/空闲页，不得承诺 SSD 取证级安全擦除。
- C09：缓存密钥必须支持版本和轮换；低磁盘优先停止/清理缓存，为核心结算保留空间。管理台必须显示状态、到期、容量与降级并支持删除。
