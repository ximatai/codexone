# 用量治理规范

- U01：请求和并发必须硬限；token/图片为兼容优先治理，金额必须标估算。没有可信单次上界 U 不得作为治理能力的通用禁用理由，也不得声称 token/金额绝对封顶。
- U02：每次 dispatch 前必须事务校验授权/归属/额度/暴露容量，记录 intent 和预留；未提交不得发送。最终化 ticket 必须预分配、总数有界，普通队列饱和不能丢已执行工作。
- U03：已知实际、估算、未知必须分开；用量完整度必须 complete/partial/unavailable，缺失不得记零。R 是运营预留，不冒充最大消耗；used+held+R 准入、实际结算超 R 必须如实入账，超预算停止新准入。
- U04：账本必须幂等，迟到用量与手工调整须去重、CAS 或等价单次合并；终态移交后不能丢弃可信迟到证据。价格/策略版本和原准入窗口必须保留。
- U05：transport、active turn、unsettled exposure 必须分开。断连不得自动释放未知暴露或退款；重启必须恢复 held 和 exposure 后再准入，按主体/身份/全局阈值断路。
- U06：无法查询的后端不得伪装自动核对；管理员释放/计收必须可审计，不得按 TTL 自动退款。未知成本由管理域承担并明确显示。
- U07：仅当全部未决项有同单位可信剩余 U 时才能展示总体数值上界，公式须避免重复已入账量。混有未知项必须标成本上界未知，本地 credit 不等于真实 token 或官方剩余额度。
