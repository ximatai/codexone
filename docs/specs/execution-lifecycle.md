# 执行与连接生命周期

## 持久执行

- E01：每个 attempt 必须在 dispatch 前持久记录身份、意图和预留；准入失败不得发送上游。
- E02：执行状态、网络状态和未知消耗必须分开。取消本地连接不证明上游未执行；不能提供跨数据库与上游的 exactly-once 保证。
- E03：对外可引用 ID 必须先持久提交主体/命名空间/账号/对象/attempt 归属，再暴露。绑定失败停止输出，不跨账号重放；缓冲大小受限。
- E04：最终化必须有预先保留的有界处理容量和单次移交路径。结算幂等，移交后的可信迟到用量仍需去重合并，不能丢失或重复扣收。
- E05：数据库失败或关闭超时以已持久 intent/预留恢复未知状态；不得依赖失败后再写一次 pending 才能恢复，不自动退款。

## 连接与任务

- E06：WS 握手只做本地认证/容量管理；首个有效 create 串行决定上游身份。绑定后连接不换账号，后续 turn 重查权限与归属。
- E07：同 lane FIFO，跨 lane 有总容量限制；每个上游 socket 单 reader、串行 writer，禁止共享迭代器并发读取或交错消息分片。
- E08：任务/continuation 必须有 owner 和单次结束路径；队列按字节与条目双限，入 task/actor mailbox 前取得容量。慢消费者/拥塞超时关闭整连接，并逐 turn 最终化。
- E09：channel inactive、超时和显式取消汇入统一关闭路径，关闭 I/O 并取消/等待子任务；网络关闭不得反向等待结算造成循环。
- E10：warmup、生成、后台执行不能混用生命周期或默认假设免费；只开放有独立契约和验收的模式。未知终态不能伪造成成功。

运行 owner 与依赖位置见 [ownership](../architecture/ownership.md)，能力与重试规则见 [protocol](protocol.md)。
