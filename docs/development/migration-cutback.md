# 合成迁移与切回操作

本方案按 O03/O04/O13 为独立旧服务→CodexOne→旧服务定义保守操作。验证脚本中的 legacy 是有独立 SQLite/额度账的合成 HTTP fixture，不是 CodexLB 实现或导入器；实际旧版本须先只读核实字段和行为，不能由本演练宣称兼容。真实导入、客户端改配和路由切换需实际授权。Desktop、真实订阅、存量会话读取和 M5 仍独立验收。

## 转换清单

| 对象 | 处理和客户端动作 |
|---|---|
| 域名、数据前缀 | 可保留公开域名以及 `/v1`、`/backend-api/codex`，仅切换受控反代目标；健康检查不得调用付费模型。实际域名 TLS 另验 |
| provider 配置 | 核对 base URL、模型目录/别名、传输/工具/图片能力和权限；换发 Key 后显式更新客户端，重新开会话 |
| 旧 Key/主体 | 原则上换发；只有验证材料和授权等价性经确认才可讨论复用。哈希不能还原原文，不直接导入旧表。建立非秘密旧引用→新主体/Key ID 映射 |
| 账号/主密钥 | 新库独立主密钥，重新 OAuth 授权并核实稳定身份/刷新。旧加密文件不当作新凭证，不共享同一旋转 refresh token；旧服务停止刷新后才能授权切换 |
| 已消耗/未知用量 | 保留旧只读证据和审计编号；新配额从经核对的剩余值开始，未知数量/金额单独保守预留，不能当作成功/退款 |
| 历史响应、工具与图片归属 | 不复制旧对象绑定或正文；旧对象保持旧服务归属，不在新服务自动续接或重放。新旧 ID/上下文不能混用；需重开会话，工具副作用须人工核对 |
| 旧备份 | 停止接单并收敛后独立一致性备份，验证私有权限/摘要/原密钥依赖；新服务不挂载旧可写库。新库另按快照维护流程备份 |

## 切换与失败停点

1. 私下记录上述转换表、回退窗口、客户端变更、旧/新不可变版本和审计编号。先演练新服务配置、权限及合成请求，保持正式入口未切；旧库绝不作为新服务 schema。
2. 入口暂停新请求，旧侧停止新的授权刷新和准入，有界等待在途。超时保持暂停，保留未知执行，不能悄悄将仍在途请求转发新侧。反代一次请求只选择一个目标，禁止自动重试或出错回落旧服务。
3. 旧侧停止后做一致性备份及最终用量快照，核对缺失区间。逐主体/Key/UTC 窗口列明已消耗和未知责任、剩余配额；无法归属的责任不能虚构到某个 Key。不能可靠表达基线时保持关闭准入，人工核对后显式给予保守的新配额。本机 fixture 只有一个主体，使用减少新配额的方式演练，不代表通用跨主体基线导入。
4. 切路由到新服务，换发 Key/重新授权账号并更新客户端。检查旧 Key 被拒、新权限正确、标准/现有前缀、文本/工具/压缩/图片与传输；桌面和真实订阅未验时保留缺口。保留新侧新增结算与 unknown，不依据 HTTP 成败推断扣费。旧侧保持停止/独立只读，不能共写或并发刷新。
5. 若切回，先暂停新入口并停止新授权/刷新、有界收敛；以独立审计记录新侧新增请求、完整费用及 unknown 数量/预留金额，并将这些责任保守加到旧侧当前配额基线。核对必须有唯一审计编号/CAS 或人工防重复机制；不能恢复旧备份余额或重放新请求来制造历史。工具副作用、未知归属和配额无法核对时保持暂停。
6. 保留新库与新密钥/备份供只读核查，确认旧侧仅使用自己的凭证。恢复旧目标与旧客户端 Key/provider，验证新 Key 不被旧服务接受、旧侧配额包含切换期责任、没有新侧重放；新会话不能在旧侧无证据续接。切回失败仍保持暂停，不执行双目标兜底。

## 合成检查

`python3 scripts/verify_migration_cutback.py --binary <codexone>` 使用独立 legacy SQLite、私有一致性备份、单目标真实 loopback HTTP 转发及实际 CodexOne 进程。检查活动请求阻止切换、暂停时拒绝、换 Key/剩余额度、不同数据前缀、实际 settled/unknown、新增责任带回旧账、备份与新账保留及不重放。fixture 不实现 WebSocket/TLS、真实 OAuth 或完整旧产品；这些能力由各自真实协议/TLS/授权场景与后续客户端验收覆盖，不能据此声明 O13 全部完成。

同 schema 的二进制回退使用同一卷和原密钥；旧快照恢复必须走[快照维护](snapshot-maintenance.md)的维护态/缺失区间核对。两者不能相互替代。实际镜像回退命令与验收入口见 [Linux 安装](linux-installation.md)。
