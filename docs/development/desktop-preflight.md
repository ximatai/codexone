# Desktop 测试候选与操作边界

此流程先准备网关候选与合成证据；真实Desktop操作前单独讨论版本、操作方式和配置变更。候选冻结不等于真实客户端兼容通过。全局状态与实际候选标识只在 [STATUS](../../STATUS.md) 维护，阶段证据见[测试准备](../changes/desktop-test-readiness/verification.md)。

## 候选内容

冻结同一份已review源码、Linux amd64运行镜像、实际二进制摘要、源码归档及SHA256SUMS；保留阶段测试命令、平台/工具链、合成配置边界和未覆盖项。镜像标签便于查找，实际使用不可变镜像ID；仅本地归档，不推送registry或部署。安装/同卷兼容回退复用[Linux安装](linux-installation.md)流程，不把恢复旧数据库当作撤销新增执行责任。

长连接/最大图片检查使用 `scripts/verify_desktop_boundaries.py`，显式传入binary及新output。duration每配置至少125秒才记录为长寿命样本，3秒只用于夹具排错。真实同一HTTP TCP连接循环，WS配置另保持单一原生WS上游连接、预热及previous_response_id多轮；取消后核对关闭、unknown/预留与无重放。最大参考图包含四图合计6MiB、图+mask合计6MiB、单图/合计/数量溢出及4MiB输入输出工具组合。图片为有效PNG容器和合成像素，精确字节上限用合法附属块填充；不代表全部编解码器、最大像素、所有图片格式/帧组合或真实提供者都接受。

外部HTTP/WS正文仍8MiB。经过Images校验的multipart转base64后，仅内部封套有9MiB预算，序列化不转义斜杠；不会授予网络请求9MiB上传或改变下游8MiB帧/队列预算。9MiB含6MiB图像base64及有界提示、参数、工具封套余量。源码实际限制与失败路径还须由socket检查核对，不能只看常量。

资源报告记录网关RSS、内核历史RSS峰值、可用时的FD/线程和存储队列/WAL回稳；线程不是Swift async task数。这个有界回归使用768MiB网关RSS门槛及相对回稳包络，Linux SDK测试容器还承载Python合成端，不能冒充独立网关cgroup或约1.6GiB目标宿主容量。完整O14仍按[容量演练](capacity.md)单独验收。

## Desktop 第一轮的验收矩阵

第一轮使用真实Desktop和合成上游，不接真实订阅，不生成真实账号额度消耗。开始前记录具体Desktop/内置客户端版本、候选源码/镜像/二进制标识、合成模型profile、端点/传输和操作者。不得用CLI或socket结果填入Desktop实际结果。

| 路径 | 操作与证据 |
|---|---|
| 配置/目录 | 使用独立临时工作区和专用Key；记录模型目录与选择、连接成功/拒绝和恢复原provider配置步骤 |
| 文本与工具 | 实际UI显示增量和终态；只用无副作用合成工具，核对工具结果提交及下一轮；不把模型返回空成功当完成 |
| 预热/压缩/续接 | 观察实际传输、generate:false、压缩输入与后续turn；正常连接内续接与断线输出读取分开 |
| 图片 | 生成→参考图编辑→主动下一次编辑；记录UI输入/输出格式、权限拒绝、数据和图片用量证据 |
| 中断 | 分别观察客户端取消、提供者提前关闭、网关重启与过期；记录旧执行unknown、新执行、已有输出能否读取和用户动作 |
| 管理核对 | 账号启停/授权/额度健康、Key权限和用量诊断与实际执行一致，未知责任不自动清除 |

中断探针先使用无工具副作用的文本，不能把Desktop的Reconnecting当作输出重读或自动重放授权。M5读取契约按[恢复证据](../evidence/client-recovery.md)观察；没有读取路径时保留缺口，不先建私有恢复协议。真实订阅、用户服务器切换和发布均另行授权。

## 操作准备与结束

讨论并确认可用的Desktop操作方式；若工具限制控制Codex本体，改由用户操作并由Agent核对网关，不绕过限制。不读取/复制个人登录缓存，不改真实旧服务。配置、图片和文本均用合成资料；截图避开凭证/授权URL，仓库和报告不保存正文/回调/主机私有配置。

使用专用测试数据目录，准备私有初始化与停止/恢复配置步骤；不让两个实例共写库，不让新旧服务并发刷新同一旋转凭证。测试后先记录执行/用量/未知责任，再按该测试owner清理合成资源；不以清库冒充退款或回退。第一轮通过后才讨论真实订阅的小规模范围。
